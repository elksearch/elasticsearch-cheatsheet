## 🧠 Logstash Architecture

```
INPUT PLUGINS          CODEC         FILTER PLUGINS        OUTPUT PLUGINS
(data sources)         (decode)      (transform)           (destinations)

beats:5044  ─────────┐              ┌─ grok               ┌─ elasticsearch
kafka       ─────────┤   JSON/Plain ├─ mutate             ├─ kafka
tcp:5000    ─────────┤   multiline  ├─ date               ├─ file
http        ─────────┤   gzip       ├─ geoip              ├─ stdout (debug)
file        ─────────┤   etc...     ├─ useragent           ├─ s3
jdbc        ─────────┘              ├─ ruby               └─ etc...
sqs         ─────────────────       ├─ translate
                                    └─ etc...

QUEUE (in-memory or persistent)
  → Decouples inputs from filters
  → Prevents data loss during filter processing
  → Persistent queue = survives Logstash restart
```

## ⚙️ Part 1 - logstash.yml Configuration

```yaml
# /etc/logstash/logstash.yml

# Pipeline settings
pipeline.id: main
pipeline.workers: 4               # default = CPU cores
pipeline.batch.size: 125          # events per batch

# Dead letter queue

xpack.monitoring.elasticsearch.username: logstash_system
xpack.monitoring.elasticsearch.password: "${LOGSTASH_SYSTEM_PASSWORD}"

# Logging
log.level: info                   # trace, debug, info, warn, error, fatal
log.format: json                  # plain or json
path.logs: /var/log/logstash

# API
api.enabled: true
api.http.host: 127.0.0.1
api.http.port: 9600

# JVM (set in jvm.options instead)
# -Xms4g
# -Xmx4g
```

## 🔧 Part 3 - Filter Plugins

### Grok (Parse Unstructured Text)

```ruby
filter {
  grok {
    match => {
      "message" => [
        "%{COMBINEDAPACHELOG}",
        "%{TIMESTAMP_ISO8601:timestamp} %{LOGLEVEL:level} \[%{DATA:thread}\] %{GREEDYDATA:log_message}"
      ]
    }
    tag_on_failure => ["_grokparsefailure"]
    overwrite => ["message"]
    named_captures_only => true
    timeout_millis => 5000
  }
}
```

### Mutate (Field Manipulation)

```ruby
filter {
  mutate {
    # Rename fields
    rename => {
      "clientip" => "source.ip"
      "request" => "url.path"
      "response" => "http.response.status_code"
    }

    # Convert field types
    convert => {
      "http.response.status_code" => "integer"
      "http.response.body.bytes"  => "integer"
    }

    # Add fields
    add_field => {
      "service.name" => "nginx"
      "service.environment" => "%{[fields][env]}"
      "event.ingested" => "%{@timestamp}"
    }

    # Remove fields
    remove_field => ["beat", "host.os", "agent.type", "ecs"]

    # String operations
    lowercase => ["user.name"]
    uppercase => ["http.request.method"]
    strip     => ["message"]
    split     => { "tags" => "," }
    join      => { "tags_array" => ", " }
    gsub      => ["url.path", "\\?.*", ""]  # remove query string

    # Merge arrays
    merge     => { "field1" => "field2" }

    # Copy field
    copy      => { "source.ip" => "client.ip" }
  }
}
```

### Date (Parse Timestamps)

```ruby
filter {
  date {
    match => ["timestamp", "dd/MMM/yyyy:HH:mm:ss Z", "ISO8601", "UNIX"]
    target => "@timestamp"
    timezone => "Asia/Kolkata"
    locale => "en"
    tag_on_failure => ["_dateparsefailure"]
  }
}
```

### Translate (Lookup Table)

```ruby
filter {
  translate {
    source => "http.response.status_code"
    target => "http.response.status_text"
    dictionary => {
      "200" => "OK"
      "201" => "Created"
      "400" => "Bad Request"
      "401" => "Unauthorized"
      "403" => "Forbidden"
      "404" => "Not Found"
      "500" => "Internal Server Error"
      "503" => "Service Unavailable"
    }
    fallback => "Unknown"

    # OR load from file (YAML, JSON, CSV)
    # dictionary_path => "/etc/logstash/status_codes.yml"
    # refresh_interval => 300
  }
}
```

### Ruby (Custom Logic)

```ruby
filter {
  ruby {
    code => '
      # Add computed field
      duration = event.get("event.duration")
      if duration
        event.set("event.duration_category",
          if duration < 100 then "fast"
          elsif duration < 500 then "normal"
          elsif duration < 2000 then "slow"
          else "very_slow"
          end
        )
      end

      # Parse JSON in a field
      raw_json = event.get("raw_payload")
      if raw_json
        begin
          parsed = JSON.parse(raw_json)
          event.set("payload", parsed)
          event.remove("raw_payload")
        rescue => e
          event.tag("_json_parse_failure")
        end
      end
    '
    tag_on_exception => "_ruby_exception"
  }
}
```

### Aggregate (Correlate Multiple Events)

```ruby
# Build a single transaction document from multiple events
filter {
  aggregate {
    task_id => "%{transaction_id}"
    code => "
      map['start_time'] ||= event.get('@timestamp')
      map['events'] ||= 0
      map['events'] += 1
      map['total_duration'] ||= 0
      map['total_duration'] += event.get('event.duration').to_f

      if event.get('event.type') == 'end'
        event.set('transaction.total_duration', map['total_duration'])
        event.set('transaction.event_count', map['events'])
        event.set('transaction.start_time', map['start_time'])
        map.delete(:task)
      end
    "
    timeout => 120
    timeout_tags => ["_aggregate_timeout"]
  }
}
```

## 🔀 Part 5 - Conditionals & Routing

### If-Else Routing

```ruby
filter {
  # Parse based on source
  if [type] == "nginx_access" {
    grok { match => { "message" => "%{COMBINEDAPACHELOG}" } }
    geoip { source => "clientip" }
  } else if [type] == "syslog" {
    grok { match => { "message" => "%{SYSLOGLINE}" } }
  } else if [fields][service] == "payment" {
    grok { match => { "message" => "%{TIMESTAMP_ISO8601:timestamp} PAYMENT %{GREEDYDATA:payment_data}" } }
    mutate { add_field => { "event.dataset" => "payment" } }
  } else {
    mutate { add_tag => ["_unknown_format"] }
  }
}

output {
  # Route to different indices
  if "payment" in [tags] {
    elasticsearch { index => "logs-payment-production" }
  } else if [log][level] == "ERROR" {
    elasticsearch { index => "logs-errors-production" }
    # Also send errors to Slack
    http {
      url => "https://hooks.slack.com/..."
      format => "message"
      content_type => "application/json"
      message => '{"text": "ERROR: %{message}"}'
    }
  } else {
    elasticsearch { index => "logs-%{[service][name]}-production" }
  }

  # Always log to file for debugging (remove in production)
  if [log][level] == "DEBUG" {
    file { path => "/tmp/logstash-debug.log" }
  }
}
```

## 🔁 Part 6 - Multiple Pipelines

### pipelines.yml

```yaml
# /etc/logstash/pipelines.yml

# Pipeline 1: Nginx logs
- pipeline.id: nginx-pipeline
  path.config: "/etc/logstash/conf.d/nginx.conf"
  pipeline.workers: 4
  pipeline.batch.size: 500
  queue.type: persisted

# Pipeline 2: Application logs
- pipeline.id: app-pipeline
  path.config: "/etc/logstash/conf.d/app.conf"
  pipeline.workers: 8
  pipeline.batch.size: 125
  queue.type: persisted
  queue.max_bytes: 2gb

# Pipeline 3: Payment logs (sensitive — smaller batches, more workers)
- pipeline.id: payment-pipeline
  path.config: "/etc/logstash/conf.d/payment.conf"
  pipeline.workers: 2
  pipeline.batch.size: 50
  queue.type: persisted

# Pipeline 4: Dead letter queue reprocessing
- pipeline.id: dlq-pipeline
  path.config: "/etc/logstash/conf.d/dlq.conf"
  pipeline.workers: 1
```

### Pipeline-to-Pipeline Communication

```ruby
# Pipeline 1: Router (sends to other pipelines)
# /etc/logstash/conf.d/router.conf
input { beats { port => 5044 } }

output {
  if [service][name] == "nginx" {
    pipeline { send_to => ["nginx-pipeline"] }
  } else if [service][name] == "payment" {
    pipeline { send_to => ["payment-pipeline"] }
  } else {
    pipeline { send_to => ["default-pipeline"] }
  }
}

# Pipeline 2: Nginx processor
# /etc/logstash/conf.d/nginx-processor.conf
input { pipeline { address => "nginx-pipeline" } }

filter {
  grok { match => { "message" => "%{COMBINEDAPACHELOG}" } }
  geoip { source => "source.ip" }
}

output {
  elasticsearch {
    index => "logs-nginx-production"
    data_stream => true
  }
}
```

## 💾 Part 7 - Persistent Queue & DLQ

### Persistent Queue

```yaml
# logstash.yml
queue.type: persisted
queue.path: /var/lib/logstash/queue
queue.max_bytes: 8gb
queue.page_capacity: 64mb
queue.drain: false   # true = drain queue before shutdown
```

```
Benefits of Persistent Queue:
  ✅ Survives Logstash restarts
  ✅ Survives Logstash crashes
  ✅ Absorbs input spikes without dropping events
  ✅ At-least-once delivery guarantee

Memory queue (default):
  ✅ Faster
  ❌ Events lost on crash/restart
  ❌ Use only for non-critical data
```

### Dead Letter Queue

```yaml
# logstash.yml
dead_letter_queue.enable: true
dead_letter_queue.max_bytes: 1gb
dead_letter_queue.storage_policy: drop_newer  # or drop_older
dead_letter_queue.retain_while_running: false
```

```ruby
# DLQ input pipeline — reprocess failed events
input {
  dead_letter_queue {
    path => "/var/lib/logstash/dead_letter_queue"
    commit_offsets => true
    pipeline_id => "main"
    sincedb_path => "/var/lib/logstash/dlq_sincedb"
  }
}

filter {
  # Inspect why it failed
  # [@metadata][dead_letter_queue][reason] = failure reason
  # [@metadata][dead_letter_queue][entry_time] = when it failed
  # [@metadata][dead_letter_queue][plugin_id] = which plugin failed

  mutate {
    add_field => {
      "dlq.reason" => "%{[@metadata][dead_letter_queue][reason]}"
      "dlq.plugin" => "%{[@metadata][dead_letter_queue][plugin_id]}"
      "dlq.entry_time" => "%{[@metadata][dead_letter_queue][entry_time]}"
    }
  }

  # Try to fix the issue that caused failure
  if "_grokparsefailure" in [@metadata][dead_letter_queue][reason] {
    mutate { add_field => { "message_raw" => "%{message}" } }
    mutate { update => { "message" => "GROK_FAILED: %{message}" } }
  }
}

output {
  elasticsearch {
    index => "logs-dlq-reprocessed"
    hosts => ["https://my-es:9200"]
    user => "logstash-writer"
    password => "${LOGSTASH_PASSWORD}"
  }
}
```

```bash

pipeline.events.in            → events entering pipeline

pipeline.events.filtered      → events filtered out
pipeline.events.duration_in_millis → total processing time
```

### Performance Tuning

```yaml
# Increase workers for CPU-bound filters (grok, ruby)
pipeline.workers: 8   # start with CPU cores, increase if needed

# Increase batch size for high-throughput, low-latency data
pipeline.batch.size: 500   # start with 125, increase until output is bottleneck

# Increase batch delay for batching efficiency
pipeline.batch.delay: 100  # wait up to 100ms to fill batch

# JVM tuning (jvm.options):
-Xms4g
-Xmx4g
# ALWAYS set Xms = Xmx

# For grok performance:
# Use timeout_millis to prevent hanging on complex patterns
grok { timeout_millis => 3000 }

# Use multiple patterns with most common first
grok {
  match => {
    "message" => [
      "%{MOST_COMMON_PATTERN}",    # try this first
      "%{LESS_COMMON_PATTERN}",    # fallback
      "%{CATCH_ALL}"               # last resort
    ]
  }
}
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| Memory queue in production | Events lost on crash | Use `queue.type: persisted` |
| No DLQ enabled | Failed events silently dropped | Enable `dead_letter_queue.enable: true` |
| Grok without timeout_millis | Catastrophic backtracking → hang | Always set `timeout_millis => 3000` |
| Too many patterns in single grok | Slow matching | Split into multiple grok or use dissect |
| Workers < CPU cores | CPU underutilized | Set workers = CPU cores for filter-heavy pipelines |
| No conditionals on output | Everything to single index | Route by service/type to different indices |
| Credentials in config files | Security risk | Use environment variables `${VAR_NAME}` |
| No monitoring enabled | Can't see what's slow | Enable xpack.monitoring or use API |
| Using Ruby filter for simple ops | Slow — JRuby overhead | Use mutate/grok/date instead |
| Logstash as load balancer for ES | Not its role | Use ES native load balancing |

## 💡 Key Principles

```
1. Persistent queue is mandatory in production
   → Memory queue = data loss on crash

2. Enable DLQ to capture failed events
   → Otherwise failures are silent

3. Pipeline workers = CPU cores (start point)
   → Tune up if filters are CPU-bound and throughput is low

4. Use dissect before grok for structured logs
   → Dissect is 10-20x faster (no regex)

5. Multiple pipelines for different data types
   → Isolate payment logs from nginx logs from app logs

6. Credentials via environment variables only
   → Never hardcode in config files

7. Conditionals reduce unnecessary processing
   → Filter only what needs filtering

8. Pipeline-to-pipeline for complex routing
   → Single entry point, route internally

9. Grok timeout prevents catastrophic backtracking
   → Always set timeout_millis

10. Monitor via API or Stack Monitoring
    → You can't tune what you can't measure
```
