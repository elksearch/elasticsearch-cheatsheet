## Beats Deep Dive
### Filebeat, Metricbeat, Packetbeat, Heartbeat, Auditbeat, Winlogbeat

> Beats are lightweight data shippers — single-purpose agents that collect specific types of data.
> While Elastic Agent supersedes individual Beats for new deployments,
> Beats remain widely used and essential knowledge for any ELK engineer.

## 🧠 Beats Overview

```
BEAT          → WHAT IT COLLECTS           → TYPICAL USE CASE
────────────────────────────────────────────────────────────
Filebeat      → Log files                  → App logs, system logs, nginx
Metricbeat    → System/service metrics     → CPU, memory, MySQL, Redis stats
Packetbeat    → Network packets            → HTTP, DNS, MySQL, Redis traffic
Heartbeat     → Uptime/availability        → Monitor endpoints, ping services
Auditbeat     → Linux audit events         → Security compliance, FIM
Winlogbeat    → Windows Event Logs         → Security events, system logs (Windows)
Functionbeat  → Serverless (Lambda/GCF)    → Cloud function logs
Custom Beat   → Anything you build        → Internal APIs, proprietary data

ALL BEATS SHARE:
  → Common configuration structure
  → Same output plugins (Elasticsearch, Logstash, Kafka, etc.)
  → Built-in TLS, authentication
  → Autodiscover (Kubernetes/Docker)
  → Monitoring via Stack Monitoring
```

## 📁 Part 1 - Filebeat (Log Shipper)

### filebeat.yml — Complete Configuration

```yaml
# /etc/filebeat/filebeat.yml

# ── INPUTS ─────────────────────────────────────────────────
filebeat.inputs:

  # Log files
  - type: log
    id: nginx-access
    enabled: true
    paths:
      - /var/log/nginx/access.log
      - /var/log/nginx/access.log.*
    exclude_files: [".gz$"]
    tags: ["nginx", "access"]
    fields:
      service.name: nginx
      service.environment: production
    fields_under_root: true
    scan_frequency: 10s
    max_bytes: 10485760   # 10MB max per line (for large logs)
    close_inactive: 5m
    clean_inactive: 72h
    ignore_older: 72h

  # JSON logs
  - type: log
    id: app-json-logs
    paths: [/var/log/myapp/*.log]
    json.keys_under_root: true
    json.message_key: message
    json.overwrite_keys: true
    json.add_error_key: true
    json.expand_keys: true      # converts a.b.c to nested {a: {b: {c}}}
    tags: ["app"]

  # Multiline (Java stack traces)
  - type: log
    id: java-app
    paths: [/var/log/java-app/*.log]
    multiline.type: pattern
    multiline.pattern: '^\d{4}-\d{2}-\d{2}'  # new log starts with date
    multiline.negate: true
    multiline.match: after
    multiline.max_lines: 500
    multiline.timeout: 5s

  # Docker container logs
  - type: container
    id: docker-logs
    paths:
      - /var/lib/docker/containers/*/*.log
    processors:
      - add_docker_metadata:
          host: "unix:///var/run/docker.sock"
      - decode_json_fields:
          fields: ["message"]
          overwrite_keys: true
          target: ""

# ── MODULES ────────────────────────────────────────────────
filebeat.config.modules:
  path: ${path.config}/modules.d/*.yml
  reload.enabled: true
  reload.period: 10s

# ── AUTODISCOVER ───────────────────────────────────────────
filebeat.autodiscover:
  providers:
    - type: kubernetes
      node: ${NODE_NAME}
      hints.enabled: true
      hints.default_config:
        type: container
        paths:
          - /var/log/containers/*${data.kubernetes.container.id}.log
      templates:
        - condition:
            contains:
              kubernetes.labels.app: "nginx"
          config:
            - type: container
              paths: [/var/log/containers/*${data.kubernetes.container.id}.log]
              processors:
                - add_kubernetes_metadata: ~

# ── PROCESSORS ─────────────────────────────────────────────
processors:
  - add_host_metadata:
      when.not.contains.tags: forwarded
  - add_cloud_metadata: ~
  - add_docker_metadata: ~
  - add_kubernetes_metadata: ~
  - drop_event:
      when:
        regexp:
          message: "^(GET|POST) /health"  # drop health check logs

# ── OUTPUT ─────────────────────────────────────────────────
output.elasticsearch:
  hosts: ["https://my-es:9200"]
  username: "filebeat-writer"
  password: "${FILEBEAT_PASSWORD}"
  ssl:
    certificate_authorities: ["/etc/filebeat/certs/ca.crt"]
  index: "filebeat-%{[agent.version]}-%{+yyyy.MM.dd}"
  pipeline: "filebeat-enrichment"
  # OR data stream:
  # preset: balanced

# OR output to Logstash
# output.logstash:
#   hosts: ["logstash:5044"]
#   ssl.enabled: true

# ── SETUP ──────────────────────────────────────────────────
setup.kibana:
  host: "http://kibana:5601"
  username: "elastic"
  password: "${ELASTIC_PASSWORD}"

setup.dashboards.enabled: true
setup.template.enabled: true
setup.ilm.enabled: true
setup.ilm.rollover_alias: "filebeat"
setup.ilm.pattern: "{now/d{yyyy.MM.dd}}-000001"
setup.ilm.policy_name: "filebeat-policy"

# ── MONITORING ─────────────────────────────────────────────
monitoring.enabled: true
monitoring.cluster_uuid: "..."
monitoring.elasticsearch:
  hosts: ["https://my-es:9200"]
  username: "beats_system"
  password: "${BEATS_SYSTEM_PASSWORD}"
```

### Filebeat Processors Reference

```yaml
processors:
  # Add host metadata
  - add_host_metadata:
      geo.name: mumbai-dc1
      geo.location: "19.07, 72.87"

  # Add cloud metadata (AWS/GCP/Azure auto-detected)
  - add_cloud_metadata: ~

  # Decode JSON
  - decode_json_fields:
      fields: ["message"]
      overwrite_keys: true

  # Drop fields
  - drop_fields:
      fields: ["log.offset", "input.type", "ecs.version"]
      ignore_missing: true

  # Rename fields
  - rename:
      fields:
        - from: "source"
          to: "log.source"

  # Drop events matching condition
  - drop_event:
      when:
        or:
          - equals:
              http.response.status_code: 200
          - contains:
              url.path: "/health"

  # Add label/tag
  - add_tags:
      tags: [production, nginx]
      target: tags

  # Script processor (JavaScript)
  - script:
      lang: javascript
      id: truncate_message
      source: >
        function process(event) {
          var msg = event.Get("message");
          if (msg && msg.length > 10000) {
            event.Put("message", msg.substring(0, 10000) + "...[truncated]");
            event.AppendTo("tags", "message_truncated");
          }
        }

  # Copy fields
  - copy_fields:
      fields:
        - from: "source.ip"
          to: "client.ip"
```

## 📊 Part 2 - Metricbeat (Metrics Collector)

### metricbeat.yml Key Configuration

```yaml
# /etc/metricbeat/metricbeat.yml

metricbeat.config.modules:
  path: ${path.config}/modules.d/*.yml
  reload.enabled: true
  reload.period: 10s

# ── SYSTEM MODULE ──────────────────────────────────────────
# /etc/metricbeat/modules.d/system.yml
- module: system
  period: 30s
  metricsets:
    - cpu
    - load
    - memory
    - network
    - process
    - process_summary
    - socket_summary
    - filesystem
    - diskio
  process.include_top_n:
    by_cpu: 5
    by_memory: 5
  cpu.metrics: ["percentages", "normalized_percentages"]
  core.metrics: ["percentages"]

# ── ELASTICSEARCH MODULE ────────────────────────────────────
# /etc/metricbeat/modules.d/elasticsearch-xpack.yml
- module: elasticsearch
  xpack.enabled: true
  period: 10s
  hosts: ["https://my-es:9200"]
  username: "remote_monitoring_user"
  password: "${REMOTE_MONITORING_PASSWORD}"
  ssl.enabled: true
  ssl.certificate_authorities: ["/etc/metricbeat/certs/ca.crt"]
  metricsets:
    - cluster_stats
```

## ❤️ Part 4 - Heartbeat (Uptime Monitoring)

### heartbeat.yml Configuration

```yaml
# /etc/heartbeat/heartbeat.yml

heartbeat.monitors:

  # HTTP/HTTPS monitors
  - type: http
    id: api-service-monitor
    name: "API Service Health Check"
    schedule: "@every 30s"
    urls:
      - "https://api-service.production.svc:8080/health"
      - "https://api-service.production.svc:8080/ready"
    check.response.status: [200]
    check.response.body: ["ok", "healthy"]
    timeout: 5s
    tags: ["api", "production"]
    fields:
      service.name: api-service
      service.environment: production

  # TCP monitor (port check)
  - type: tcp
    id: elasticsearch-port-monitor
    name: "Elasticsearch TCP Check"
    schedule: "@every 10s"
    hosts: ["my-es:9200"]
    timeout: 3s

  # ICMP monitor (ping)
  - type: icmp
    id: host-ping-monitor
    name: "Host Ping"
    schedule: "@every 60s"
    hosts: ["10.0.0.1", "10.0.0.2", "10.0.0.3"]
    timeout: 3s

  # Browser monitor (Synthetic - requires Elastic Agent)
  - type: browser
    id: checkout-flow-monitor
    name: "E-Commerce Checkout Flow"
    schedule: "@every 5m"
    source:
      inline:
        script: |-
          step('Load Home Page', async () => {
            await page.goto('https://mysite.com');
          });
          step('Search Product', async () => {
            await page.click('#search-box');
            await page.type('#search-box', 'elasticsearch');
            await page.press('#search-box', 'Enter');
          });
          step('Add to Cart', async () => {
            await page.click('.add-to-cart');
          });
```

## 🔐 Part 5 - Auditbeat (Linux Audit)

### auditbeat.yml Configuration

```yaml
# /etc/auditbeat/auditbeat.yml

auditbeat.modules:

  # Auditd module (Linux audit framework)
  - module: auditd
    resolve_ids: true
    failure_mode: silent
    backlog_limit: 8196
    rate_limit: 0
    include_raw_message: false
    include_warnings: false
    audit_rules: |
      # Monitor privileged commands
      -a always,exit -F arch=b64 -S execve -F uid!=0 -k user_commands
      -a always,exit -F arch=b64 -S execve -F uid=0 -k admin_commands

      # Monitor file changes in critical directories
      -w /etc/passwd -p wa -k passwd_changes
      -w /etc/shadow -p wa -k shadow_changes
      -w /etc/sudoers -p wa -k sudoers_changes
      -w /etc/ssh/sshd_config -p wa -k sshd_config

      # Monitor network configuration
      -a always,exit -F arch=b64 -S bind -k network_bind
      -a always,exit -F arch=b64 -S connect -k network_connect

      # Monitor kernel module loading
      -a always,exit -F arch=b64 -S init_module -S delete_module -k kernel_modules

  # File Integrity Module (FIM)
  - module: file_integrity
    paths:
      - /bin
      - /usr/bin
      - /usr/local/bin
      - /sbin
      - /usr/sbin
      - /etc
    exclude_files:
      - '(?i)\.sw[nop]$'
      - '~$'
      - '/\.git($|/)'
    scan_at_start: true
    scan_rate_per_sec: 50 MiB
    max_file_size: 100 MiB
    hash_types: [sha1]
    recursive: true

  # System module
  - module: system
    datasets:
      - host
      - login
      - package
      - process
      - socket
      - user
    state.period: 12h
    user.detect_password_changes: true
    login.wtmp_file_pattern: /var/log/wtmp*
    login.btmp_file_pattern: /var/log/btmp*
```

```yaml
    # 4625: Failed logon
```

```yaml
output.elasticsearch:

  ssl:
    enabled: true
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| Not setting `fields_under_root: true` | Fields nested under `fields.*` | Add `fields_under_root: true` |
| `json.keys_under_root` without `overwrite_keys` | Duplicate fields | Add `overwrite_keys: true` |
| No sincedb for file input | Re-reads from beginning on restart | Default sincedb in data path is fine |
| Multiline pattern wrong | Multiline events not joined | Test regex at regex101.com first |
| No close_inactive setting | File handles leak | Set `close_inactive: 5m` |
| ignore_older not set | Reads all historical logs on first run | Set `ignore_older: 72h` |
| Shipping to Elasticsearch directly without ILM | Index grows indefinitely | Enable `setup.ilm.enabled: true` |
| No pipeline for enrichment | Raw data in ES | Set `pipeline: my-pipeline` in output |
| Too many file inputs | High CPU for inotify | Consolidate paths, use globs |
| Credentials in config file | Security risk | Use keystore instead |

## 💡 Key Principles

```
1. Elastic Agent > Beats for new deployments
   → Beats still used in legacy setups and specific use cases

2. Modules provide pre-built config + dashboards
   → Always use modules when available (nginx, mysql, system, etc.)

3. Fields under root for clean ECS documents
   → fields_under_root: true + overwrite_keys: true

4. Keystore for all credentials
   → Never hardcode passwords in config files

5. ILM and index templates via setup command
   → filebeat setup --index-management before first run

6. Multiline config for multi-line log formats
   → Java stack traces, Python tracebacks need multiline

7. Autodiscover for Kubernetes/Docker
   → No static path configuration needed

8. Processors for data transformation
   → drop_event, drop_fields, add_host_metadata at Beat level

9. Sincedb tracks file reading position
   → Never delete sincedb unless you want to re-read from start

10. Monitor beats via Stack Monitoring
    → beats.monitoring in config or xpack.monitoring in logstash
```
