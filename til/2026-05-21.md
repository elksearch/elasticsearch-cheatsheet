> It automates deployment, scaling, upgrades, and certificate management.

## 🧠 Why ECK?

```
WITHOUT ECK (manual K8s):
  → Write StatefulSets for each ES node role
  → Manage certificates manually (every 90 days!)
  → Rolling upgrades = complex scripting
  → Scaling = manual StatefulSet updates
  → Keystore management = manual secrets
  → No health awareness (scheduler doesn't know ES health)

WITH ECK:
  → Declare desired state → operator manages everything
  → Auto-cert rotation (TLS handled completely)
  → Rolling upgrades = just change version number
  → Scaling = change count in YAML
  → Keystore → Kubernetes Secrets
  → Health-aware upgrades (waits for cluster GREEN)

ECK OPERATOR MANAGES:
  ✅ Certificate lifecycle (CA + node certs)
  ✅ Cluster formation (discovery, bootstrap)
  ✅ Rolling upgrades (node by node)
  ✅ Password management (elastic user secret)
  ✅ Keystore (from K8s Secrets)
  ✅ Node configuration (elasticsearch.yml)
  ✅ JVM options
  ✅ Persistent volumes
  ✅ Service exposure
```

## 🚀 Part 1 — Installation

### Install ECK Operator

```bash
# Method 1: Helm (Recommended)
helm repo add elastic https://helm.elastic.co
helm repo update

helm install elastic-operator elastic/eck-operator \
  --namespace elastic-system \
  --create-namespace \
  --set config.logVerbosity=0 \
  --set config.metricsPort=8080

# Verify installation
kubectl get pods -n elastic-system
kubectl get crd | grep elastic.co

# CRDs installed:
# elasticsearch.elasticsearch.k8s.elastic.co
# kibana.kibana.k8s.elastic.co
# apmserver.apm.k8s.elastic.co
# beat.beat.k8s.elastic.co
# elasticsearchautoscaler.autoscaling.k8s.elastic.co
# logstash.logstash.k8s.elastic.co
# stackconfigpolicy.stackconfigpolicy.k8s.elastic.co

# Method 2: kubectl
kubectl create -f https://download.elastic.co/downloads/eck/2.14.0/crds.yaml
kubectl apply -f https://download.elastic.co/downloads/eck/2.14.0/operator.yaml

# Operator logs
kubectl logs -n elastic-system -l control-plane=elastic-operator -f
```

## 📋 Part 2 — Basic Elasticsearch Deployment

### Single-Node (Development)

```yaml
# es-dev.yaml
apiVersion: elasticsearch.k8s.elastic.co/v1
kind: Elasticsearch
metadata:
  name: dev-cluster
  namespace: elastic
spec:
  version: 9.0.2
  nodeSets:
    - name: default
      count: 1
      config:
        node.store.allow_mmap: false   # needed in some K8s environments
      podTemplate:
        spec:
          containers:
            - name: elasticsearch
              env:
                - name: ES_JAVA_OPTS
                  value: "-Xms1g -Xmx1g"
              resources:
                limits:
                  memory: 2Gi
                  cpu: 1000m
                requests:
                  memory: 2Gi
                  cpu: 500m
      volumeClaimTemplates:
        - metadata:
            name: elasticsearch-data
          spec:
            accessModes: [ReadWriteOnce]
            resources:
              requests:
                storage: 10Gi
            storageClassName: standard
```

```bash
kubectl apply -f es-dev.yaml -n elastic

# Check status
kubectl get elasticsearch -n elastic
kubectl get pods -l elasticsearch.k8s.elastic.co/cluster-name=dev-cluster -n elastic

# Get elastic password
kubectl get secret dev-cluster-es-elastic-user -n elastic -o jsonpath='{.data.elastic}' | base64 -d

# Port-forward to access locally
kubectl port-forward svc/dev-cluster-es-http 9200 -n elastic

# Test
curl -k -u "elastic:$(kubectl get secret dev-cluster-es-elastic-user -n elastic -o jsonpath='{.data.elastic}' | base64 -d)" https://localhost:9200
```

## 🏗️ Part 3 — Production Multi-Tier Cluster

### Complete Production Cluster

```yaml
# es-production.yaml
apiVersion: elasticsearch.k8s.elastic.co/v1
kind: Elasticsearch
metadata:
  name: production
  namespace: elastic
spec:
  version: 9.0.2

  # HTTP service configuration
  http:
    service:
      spec:
        type: ClusterIP   # LoadBalancer for external access

  # Secure settings (from Kubernetes secrets)
  secureSettings:
    - secretName: gcs-credentials
      entries:
        - key: gcs.client.default.credentials_file
          path: gcs.client.default.credentials_file

  nodeSets:

    # ── DEDICATED MASTERS (3 nodes) ─────────────────────────
    - name: master
      count: 3
      config:
        node.roles: [master]
        cluster.name: production
        xpack.ml.enabled: false
      podTemplate:
        metadata:
          labels:
            node-type: master
        spec:
          affinity:
            # Spread masters across zones
            podAntiAffinity:
              requiredDuringSchedulingIgnoredDuringExecution:
                - labelSelector:
                    matchLabels:
                      elasticsearch.k8s.elastic.co/cluster-name: production
                      elasticsearch.k8s.elastic.co/node-master: "true"
                  topologyKey: topology.kubernetes.io/zone
          containers:
            - name: elasticsearch
              env:
                - name: ES_JAVA_OPTS
                  value: "-Xms4g -Xmx4g"
              resources:
                limits:
                  memory: 8Gi
                  cpu: 2000m
                requests:
                  memory: 8Gi
                  cpu: 500m
          initContainers:
            - name: sysctl
              securityContext:
                privileged: true
                runAsUser: 0
              command: ['sh', '-c', 'sysctl -w vm.max_map_count=262144']
      volumeClaimTemplates:
        - metadata:
            name: elasticsearch-data
          spec:
            accessModes: [ReadWriteOnce]
            resources:
              requests:
                storage: 50Gi
            storageClassName: fast-ssd

    # ── HOT DATA NODES (6 nodes) ─────────────────────────────
    - name: hot
      count: 6
      config:
        node.roles: [data_hot, data_content, ingest]
        node.attr.data: hot
        cluster.name: production
      podTemplate:
        metadata:
          labels:
            node-type: hot
        spec:
          affinity:
            podAntiAffinity:
              preferredDuringSchedulingIgnoredDuringExecution:
                - weight: 100
                  podAffinityTerm:
                    labelSelector:
                      matchLabels:
                        elasticsearch.k8s.elastic.co/cluster-name: production
                    topologyKey: kubernetes.io/hostname
          nodeSelector:
            node-pool: elastic-hot
          tolerations:
            - key: dedicated
              operator: Equal
              value: elastic-hot
              effect: NoSchedule
          containers:
            - name: elasticsearch
              env:
                - name: ES_JAVA_OPTS
                  value: "-Xms30g -Xmx30g"
              resources:
                limits:
                  memory: 64Gi
                  cpu: 16000m
                requests:
                  memory: 64Gi
                  cpu: 4000m
          initContainers:
            - name: sysctl
              securityContext:
                privileged: true
                runAsUser: 0
              command: ['sh', '-c', 'sysctl -w vm.max_map_count=262144']
      volumeClaimTemplates:
        - metadata:
            name: elasticsearch-data
          spec:
            accessModes: [ReadWriteOnce]
            resources:
              requests:
                storage: 2Ti
            storageClassName: premium-ssd

    # ── WARM DATA NODES (4 nodes) ────────────────────────────
    - name: warm
      count: 4
      config:
        node.roles: [data_warm]
        node.attr.data: warm
        cluster.name: production
      podTemplate:
        metadata:
          labels:
            node-type: warm
        spec:
          nodeSelector:
            node-pool: elastic-warm
          containers:
            - name: elasticsearch
              env:
                - name: ES_JAVA_OPTS
                  value: "-Xms16g -Xmx16g"
              resources:
                limits:
                  memory: 32Gi
                  cpu: 8000m
                requests:
                  memory: 32Gi
                  cpu: 2000m
      volumeClaimTemplates:
        - metadata:
            name: elasticsearch-data
          spec:
            accessModes: [ReadWriteOnce]
            resources:
              requests:
                storage: 8Ti
            storageClassName: standard-ssd

    # ── COLD/FROZEN NODES (2 nodes) ──────────────────────────
    - name: frozen
      count: 2
      config:
        node.roles: [data_cold, data_frozen]
        node.attr.data: cold
        cluster.name: production
        xpack.searchable.snapshot.shared_cache.size: 100gb
      podTemplate:
        spec:
          containers:
            - name: elasticsearch
              env:
                - name: ES_JAVA_OPTS
                  value: "-Xms8g -Xmx8g"
              resources:
                limits:
                  memory: 16Gi
                  cpu: 4000m
                requests:
                  memory: 16Gi
                  cpu: 1000m
      volumeClaimTemplates:
        - metadata:
            name: elasticsearch-data
          spec:
            accessModes: [ReadWriteOnce]
            resources:
              requests:
                storage: 200Gi
            storageClassName: standard

    # ── ML NODES (2 nodes) ───────────────────────────────────
    - name: ml
      count: 2
      config:
        node.roles: [ml, remote_cluster_client]
        cluster.name: production
        xpack.ml.max_machine_memory_percent: 50
      podTemplate:
        spec:
          containers:
            - name: elasticsearch
              env:
                - name: ES_JAVA_OPTS
                  value: "-Xms16g -Xmx16g"
              resources:
                limits:
                  memory: 64Gi
                  cpu: 32000m
                requests:
                  memory: 64Gi
                  cpu: 8000m
      volumeClaimTemplates:
        - metadata:
            name: elasticsearch-data
          spec:
            accessModes: [ReadWriteOnce]
            resources:
              requests:
                storage: 500Gi
            storageClassName: fast-ssd
```

## 📊 Part 4 — Kibana Deployment

```yaml
# kibana-production.yaml
apiVersion: kibana.k8s.elastic.co/v1
kind: Kibana
metadata:
  name: production
  namespace: elastic
spec:
  version: 9.0.2
  count: 2   # HA Kibana

  elasticsearchRef:
    name: production   # automatically connects to our ES cluster

  http:
    service:
      spec:
        type: LoadBalancer
    tls:
      selfSignedCertificate:
        disabled: false

  config:
    server.publicBaseUrl: "https://kibana.mycompany.com"
    xpack.fleet.enabled: true
    xpack.fleet.packages:
      - name: system
        version: latest
      - name: elastic_agent
        version: latest
    xpack.encryptedSavedObjects.encryptionKey: "${ENCRYPTION_KEY}"

  podTemplate:
    spec:
      containers:
        - name: kibana
          resources:
            limits:
              memory: 2Gi
              cpu: 2000m
            requests:
              memory: 2Gi
              cpu: 500m
          env:
            - name: ENCRYPTION_KEY
              valueFrom:
                secretKeyRef:
                  name: kibana-encryption-key
                  key: key
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  kibana.k8s.elastic.co/name: production
              topologyKey: kubernetes.io/hostname
```

## 🔒 Part 5 — TLS Configuration

### ECK Auto-Manages TLS

```
ECK CREATES AUTOMATICALLY:
  1. Internal CA certificate (valid 3 years, auto-renewed)
  2. Per-node HTTP certificates
  3. Per-node transport certificates
  4. elastic user password
  5. kibana_system user password

ALL STORED AS KUBERNETES SECRETS:
  {cluster-name}-es-http-certs-internal
  {cluster-name}-es-http-certs-public
  {cluster-name}-es-transport-certs-public
  {cluster-name}-es-elastic-user
  {cluster-name}-es-internal-users
```

### Custom TLS Certificate

```yaml
# Use your own CA/certificates
apiVersion: elasticsearch.k8s.elastic.co/v1
kind: Elasticsearch
metadata:
  name: production
spec:
  http:
    tls:
      certificate:
        secretName: my-es-tls-secret   # must contain tls.crt, tls.key, ca.crt

  transport:
    tls:
      certificate:
        secretName: my-transport-tls-secret
      certificateAuthorities:
        secretName: my-transport-ca-secret
```

```bash
# Get auto-generated CA for use in clients
kubectl get secret production-es-http-certs-public -n elastic -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt

# Get elastic password
ELASTIC_PASSWORD=$(kubectl get secret production-es-elastic-user -n elastic -o jsonpath='{.data.elastic}' | base64 -d)

# Test with CA
curl --cacert ca.crt -u "elastic:${ELASTIC_PASSWORD}" https://production-es-http.elastic.svc.cluster.local:9200
```

## 🔄 Part 7 — Upgrades & Scaling

### Version Upgrade (Rolling)

```bash
# Simply change version — ECK handles rolling upgrade automatically!
kubectl edit elasticsearch production -n elastic
# Change: spec.version: 9.0.2 → 9.1.0

# Or with patch:
kubectl patch elasticsearch production -n elastic --type='merge' \
  -p '{"spec":{"version":"9.1.0"}}'

# Monitor upgrade progress
kubectl get elasticsearch production -n elastic -w

# Watch pods being upgraded
kubectl get pods -l elasticsearch.k8s.elastic.co/cluster-name=production -n elastic -w

# ECK upgrade order: ML → data → masters (health-aware)
```

### Scaling

```bash
# Scale hot nodes from 6 to 8
kubectl patch elasticsearch production -n elastic --type='json' \
  -p='[{"op": "replace", "path": "/spec/nodeSets/1/count", "value": 8}]'

# Monitor scaling
kubectl get elasticsearch production -n elastic
# PHASE should go: operational → ApplyingChanges → operational
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| No pod anti-affinity | All masters on same node | Add zone/hostname anti-affinity |
| No resource limits | Pods evicted under pressure | Always set requests = limits for ES |
| vm.max_map_count not set | ES fails to start | Add sysctl initContainer |
| Wrong storage class | Slow performance or wrong provisioner | Use SSD storage class for hot nodes |
| Not using nodeSelector for tiers | Hot pods on warm nodes | Label nodes + nodeSelector in spec |
| Single Kibana instance | Kibana SPOF | Always count: 2 minimum |
| Not monitoring ECK operator | Silent failures | Watch operator logs + events |
| Upgrading ECK operator with large version jump | Incompatibility | Upgrade one major version at a time |
| No PodDisruptionBudget | Simultaneous node drains during upgrades | ECK manages PDB automatically |
| Storing elastic password in app code | Security risk | Mount secret as env var in pod |

## 💡 Key Principles

```
1. ECK operator = production Kubernetes deployment standard
   → Manual StatefulSets for ES are error-prone

2. Zone anti-affinity for masters is mandatory
   → Without it, all 3 masters can land on same AZ → single AZ failure = RED

3. Resource requests = limits for Elasticsearch
   → Prevents OOM kills, ensures stable JVM heap

4. vm.max_map_count via initContainer
   → Required for ES on Kubernetes, easy to forget

5. ECK manages TLS automatically
   → No manual cert rotation needed ever

6. secureSettings from Kubernetes Secrets
   → Never put credentials in elasticsearch.yml

7. Separate node pools per tier in cloud
   → Hot: NVMe SSD instances, Warm: standard SSD, Frozen: cheap storage

8. version change = automatic rolling upgrade
   → ECK is health-aware: waits for GREEN before next node

9. count change = automatic scaling
   → Scaling up/down managed safely by ECK

10. Monitor ECK operator logs for debugging
    → All decisions and errors logged by operator
```
