## 🧠 Kibana Architecture

```
KIBANA SERVER
  → Node.js application
  → Connects to Elasticsearch via kibana_system user
  → Stores config/dashboards/saved objects in .kibana* indices
  → Serves UI to browsers

KIBANA INDICES:
  .kibana-8.x          → saved objects (dashboards, visualizations)
  .kibana_task_manager → background tasks (alerts, transforms)
  .kibana_security_session → user sessions

SPACES:
  → Isolated workspaces within Kibana
  → Separate dashboards, data views, saved objects per space
  → RBAC applied per space
```

## 🔍 Part 1 - Discover (Data Exploration)

### Discover Best Practices

```
Discover = ad-hoc log/data exploration tool

Key features:
  → ES|QL mode (new — recommended)
  → KQL mode (legacy — Kibana Query Language)
  → Field statistics sidebar
  → Pattern analysis (automatic log clustering)
  → Time range selector
  → Save searches for reuse in dashboards
```

### ES|QL in Discover

```sql
-- Filter and explore
FROM logs-nginx-production
| WHERE @timestamp >= NOW() - 1 HOUR
| WHERE log.level == "ERROR"
| KEEP @timestamp, service.name, message, error.message
| SORT @timestamp DESC
| LIMIT 100

-- Pattern analysis
FROM logs-nginx-production
| WHERE @timestamp >= NOW() - 24 HOURS
| STATS count = COUNT(*) BY message
| SORT count DESC
| LIMIT 20

-- Find slow requests
FROM logs-nginx-production
| WHERE @timestamp >= NOW() - 1 HOUR
| WHERE event.duration > 5000  -- ms
| STATS 
    count = COUNT(*),
    avg_duration = AVG(event.duration),
    p99 = PERCENTILE(event.duration, 99)
  BY url.path
| SORT avg_duration DESC

-- Correlate with trace ID
FROM logs-*-production
| WHERE trace.id == "abc123def456"
| SORT @timestamp ASC
| KEEP @timestamp, service.name, log.level, message, span.id
```

### KQL (Kibana Query Language) Quick Reference

```
# Exact term match
log.level: ERROR
service.name: "api-service"

# Range
http.response.status_code >= 500
@timestamp > "2026-05-10T00:00:00"

# Wildcard
url.path: /api/*
message: *timeout*

# Boolean
log.level: ERROR AND service.name: api-service
log.level: ERROR OR log.level: WARN
NOT service.environment: staging

# Nested
NOT (log.level: DEBUG OR log.level: TRACE)

# Exists
error.message: *

# Phrase match
message: "connection refused"
```

### Field Statistics

```
In Discover → click any field name in left sidebar → field statistics:
  → Top 5 values with counts
  → % of documents containing this field
  → Min/max for numeric fields
  → Distribution graph

Use for:
  → Quick cardinality check
  → Unexpected values
  → Data quality validation
```

## 📊 Part 2 - Lens (Visualizations)

### Lens Visualization Types

```
Bar chart          → compare categories over time or across groups
Line chart         → trends over time
Area chart         → cumulative trends
Pie / Donut        → proportions of a whole
Metric             → single big number KPI
Data table         → tabular data with sorting
Treemap            → hierarchical proportions
Heatmap            → correlate two dimensions
Gauge              → progress toward a target
Goal               → target achievement
Tag cloud          → term frequency visualization
Mosaic             → proportion across two categories
Waffle             → proportion as filled grid
Partition          → hierarchical treemap variant
Layered chart      → multiple chart types on one canvas
```

### Lens Formula Examples

```
# Error rate %
count(kql='log.level: ERROR') / count() * 100

# P99 latency in ms
percentile(event.duration, percentile=99) / 1000

# Apdex score
(
  count(kql='event.duration < 500') +
  count(kql='event.duration >= 500 AND event.duration < 2000') / 2
) / count()

# Rate (per minute)
count() / 60

# Moving average (7-day)
moving_average(count(), window=7)

# Derivative (change rate)
differences(count())

# Cumulative sum
cumulative_sum(count())

# Comparison to previous period
count() / count(shift='1w') - 1
```

### Time Shift Comparison

```
# In Lens formula:
count()                     → current period count
count(shift='1w')           → same period 1 week ago
count(shift='1d')           → same period 1 day ago

# Use case: week-over-week error rate comparison
# Add two layers to chart:
# Layer 1: count(kql='log.level: ERROR')
# Layer 2: count(kql='log.level: ERROR', shift='1w')
```

### Canvas SQL Expression

```sql
# Canvas uses SQL or Elasticsearch DSL

| essql
  query="
    SELECT
      service.name,
      COUNT(*) as request_count,
      AVG(event.duration) as avg_duration_ms
```

## ⚙️ Part 5 - Transforms

### What Are Transforms?

```
Transforms = pre-compute aggregations and store results as new indices

Use cases:
  → Pivot table: raw events → aggregated summaries
  → Latest transform: keep only most recent document per entity
  → Latency dashboard: pre-compute hourly stats
  → User behavior analysis

Types:
  PIVOT  → group by + aggregations → summary index
  LATEST → latest document per entity → lookup index
```

### Pivot Transform Example

```bash
PUT _transform/hourly-service-stats
{
  "source": {
    "index": ["logs-nginx-production"],
    "query": {
      "range": { "@timestamp": { "gte": "now-30d" } }
    }
  },
  "pivot": {
    "group_by": {
      "service_name": { "terms": { "field": "service.name" } },
      "hour": {
        "date_histogram": {
          "field": "@timestamp",
          "calendar_interval": "1h"
        }
      }
    },
    "aggregations": {
      "request_count": { "value_count": { "field": "@timestamp" } },
      "error_count": {
        "filter": { "term": { "log.level": "ERROR" } }
      },
      "avg_duration_ms": { "avg": { "field": "event.duration" } },
      "p99_duration_ms": { "percentiles": { "field": "event.duration", "percents": [99] } }
    }
  },
  "dest": {
    "index": "service-hourly-stats"
  },
  "sync": {
    "time": {
      "field": "@timestamp",
      "delay": "60s"
    }
  },
  "frequency": "5m",
  "settings": {
    "max_page_search_size": 5000
  }
}

# Start transform
POST _transform/hourly-service-stats/_start

# Check status
GET _transform/hourly-service-stats/_stats

# Preview transform (test before running)
POST _transform/_preview
{
  "source": { "index": ["logs-nginx-production"] },
  "pivot": { ... }
}
```

### Latest Transform (Entity-Centric)

```bash
PUT _transform/latest-service-status
{
  "source": {
    "index": ["logs-nginx-production"]
  },
  "latest": {
    "unique_key": ["service.name"],
    "sort": "@timestamp"
  },
  "dest": {
    "index": "latest-service-events"
  },
  "sync": {
    "time": {
      "field": "@timestamp",
      "delay": "30s"
    }
  },
  "frequency": "1m"
}
# Result: one document per service.name, showing LATEST event for each
```

## 🔔 Part 6 - Alerting Deep Dive

### Rule Types

```
Stack rules:
  elasticsearch_query → run ES|QL/DSL, alert when results match condition
  index_threshold     → alert when doc count crosses threshold
  tracking_containment → geo-based alerts

Observability rules:
  metrics.alert.threshold → Metric threshold alert
  logs.alert.document.count → Log count threshold
  apm.anomaly            → ML anomaly in APM data
  slo.burn_rate          → SLO burn rate alert

Security rules (SIEM):
  Custom query
  Threshold
  EQL (Event Query Language)
  ML job
```

### ES|QL Alert Rule

```bash
POST kbn:/api/alerting/rule
{
  "name": "Error Spike Alert",
  "rule_type_id": ".es-query",
  "consumer": "alerts",
  "schedule": { "interval": "1m" },
  "params": {
    "searchType": "esqlQuery",
    "esqlQuery": {
      "esql": "FROM logs-*-production | WHERE @timestamp >= NOW() - 5 MINUTES | WHERE log.level == \"ERROR\" | STATS count = COUNT(*)"
    },
    "timeField": "@timestamp",
    "timeWindowSize": 5,
    "timeWindowUnit": "m",
    "threshold": [100],
    "thresholdComparator": ">"
  },
  "actions": [
    {
      "id": "slack-connector-id",
      "group": "query matched",
      "params": {
        "message": "Alert: {{context.hits}} errors in last 5 minutes on {{context.date}}"
      }
    }
  ]
}
```

## 🔲 Part 7 - Spaces

### What Are Spaces?

```
Spaces = isolated workspaces within Kibana
  → Each space has its own:
    - Dashboards
    - Data views
    - Saved searches
    - Visualizations
    - Alerts
    - Cases

  → Users can have access to specific spaces only
  → Same Elasticsearch data, different Kibana views

Use cases:
  → Multi-team: ops, dev, security each have their space
  → Multi-tenant: customer A sees only their dashboards
  → Environment separation: prod vs staging Kibana views
  → Compliance: audit team has read-only space
```

### Spaces Management

```bash
# Create space
POST kbn:/api/spaces/space
{
  "id": "platform-team",
  "name": "Platform Team",
  "description": "Platform engineering dashboards",
  "color": "#00bfb3",
  "initials": "PT",
  "imageUrl": "",
  "disabledFeatures": []
}

# Get all spaces
GET kbn:/api/spaces/space

# Copy saved objects to another space
POST kbn:/api/spaces/_copy_saved_objects
{
  "spaces": ["security-team"],
  "objects": [
    { "type": "dashboard", "id": "error-overview-dashboard" }
  ],
  "includeReferences": true,
  "overwrite": false
}

# Role assignment per space
POST kbn:/api/security/role/platform-viewer
{
  "kibana": [
    {
      "spaces": ["platform-team"],
      "base": [],
      "feature": {
        "dashboard": ["read"],
        "discover": ["read"],
        "visualize": ["read"]
      }
    }
  ]
}
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| Using exact `now` in saved searches | Dashboard not cached by Kibana | Use `now/m`, `now/h` for relative time |
| No spaces for multi-team | Everyone sees everything | Create spaces per team with RBAC |
| Downloading full Kibana backup from .kibana index | Brittle, ES version-specific | Use Saved Objects export API instead |
| Running heavy transforms without sync delay | Misses recent data | Set sync.time.delay to at least 60s |
| Not scheduling transform preview first | Transform produces wrong output | Always run _preview before starting |
| Canvas with no caching | Slow refresh | Set appropriate auto-refresh interval |
| Alerting without testing connectors | Alerts fire but notifications fail | Test connector before creating rules |
| Not using Lens formulas for computed metrics | Incorrect rate calculations | Use count() / timeWindow for rates |
| Dashboards shared without space isolation | Cross-team data visibility | Use spaces + RBAC for isolation |
| Dev Tools console left open to public | Security risk | Kibana RBAC restricts Dev Tools access |

## 💡 Key Principles

```
1. ES|QL in Discover > KQL for complex queries
   → More powerful, readable, portable

2. Lens formulas for all computed metrics
   → Error rate = count(kql='ERROR') / count() * 100

3. Time shift for period-over-period comparisons
   → count(shift='1w') is built into Lens

4. Spaces = mandatory for multi-team environments
   → One space per team, RBAC per space

5. Round 'now' in saved objects
   → now/m or now/h enables Kibana request caching

6. Transforms for pre-computed dashboards
   → Hourly/daily stats queries → instant vs seconds

7. Use Search Profiler before optimizing queries
   → Visualizes exactly where query time goes

8. Grok Debugger for pipeline development
   → Test patterns interactively before deploying

9. Export saved objects via API for version control
   → Track dashboard changes in git

10. Alerting → SLO burn rate rules first
    → More actionable than raw metric thresholds
```
