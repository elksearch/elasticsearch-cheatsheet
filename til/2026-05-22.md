## Elasticsearch Connectors & Web Crawler
### Enterprise Content Search, SharePoint, Confluence, Databases, Web Crawler

> Elastic Connectors bring enterprise data into Elasticsearch without custom pipelines.
> From SharePoint to databases to websites — connectors ingest, sync, and index content automatically.
> This powers enterprise search, RAG knowledge bases, and unified observability.

## 🧠 Core Concepts

```
CONNECTOR = data pipeline between external data source and Elasticsearch
  → Extracts data from source
  → Transforms to Elasticsearch documents
  → Syncs changes (incremental)
  → Handles authentication, pagination, rate limiting

TWO DEPLOYMENT MODES:
  NATIVE (Elastic Cloud):
    → Hosted by Elastic
    → No infrastructure to manage
    → Available for: SharePoint, Confluence, Google Drive, Jira, etc.

  CONNECTOR CLIENT (Self-managed):
    → You run the connector as a service
    → Connect to YOUR data sources
    → Available for: all connectors
    → More control over network access

SYNC TYPES:
  Full sync:        Ingests ALL data from source
  Incremental sync: Only ingests NEW/CHANGED data since last sync
  Access control:   Syncs document-level permissions (DLS)

USE CASES:
  → Enterprise search (search SharePoint + Confluence + databases)
  → RAG knowledge base (index docs for AI Q&A)
  → Unified observability (bring in CMDB, ServiceNow data)
  → Compliance (index all company documents)
```

## ⚙️ Part 2 — Connector Client Setup

### Install and Run Connector Service

```bash
# Method 1: Docker (Recommended)
docker run -d \
  --name elastic-connectors \
  -e ELASTICSEARCH_HOST=https://my-es:9200 \
  -e ELASTICSEARCH_API_KEY=your-api-key \
  docker.elastic.co/enterprise-search/elastic-connectors:9.0.2

# Method 2: Python package
pip install elastic-connectors

# Run
elastic-ingest \
  --config-file /path/to/config.yml

# config.yml for connector service
cat > config.yml << 'EOF'
elasticsearch:
  host: https://my-es:9200
  api_key: your-api-key-here

connector_id: connector-abc123

# Service settings
service:
  log_level: INFO
  max_concurrent_syncs: 3
  queue_max_size: 1024
  queue_timeout: 120
EOF
```

## 🗄️ Part 3 — Database Connectors

### PostgreSQL Connector

```bash
# Step 1: Create connector via Kibana UI
# Search → Content → Connectors → Create connector → PostgreSQL

# Step 2: Configure (in Kibana UI or API)
POST _connector
{
  "name": "PostgreSQL Orders",
  "service_type": "postgresql",
  "index_name": "orders-from-postgres"
}

# Step 3: Set configuration
PUT _connector/CONNECTOR_ID/_configuration
{
  "values": {
    "host": "postgres-server.mycompany.com",
    "port": "5432",
    "database": "orders_db",
    "username": "readonly_user",
    "password": "secure_password",
    "tables": "orders,order_items,customers",
    "ssl_enabled": true,
    "schema": "public",

    # Sync rules
    "fetch_size": 1000
  }
}

# Step 4: Trigger full sync
POST _connector/CONNECTOR_ID/_sync_jobs
{
  "job_type": "full"
}

# Step 5: Check sync status
GET _connector/CONNECTOR_ID/_sync_jobs?status=pending,in_progress,completed

# Step 6: View indexed documents
GET orders-from-postgres/_count
GET orders-from-postgres/_search { "size": 5 }
```

## 📁 Part 4 — SharePoint Online Connector

```bash
# Prerequisites:
# 1. Azure App Registration with permissions:
#    - Sites.Read.All (SharePoint)
#    - User.Read.All (Microsoft Graph)
#    - Files.Read.All

POST _connector
{
  "name": "SharePoint Online",
  "service_type": "sharepoint_online",
  "index_name": "sharepoint-content"
}

PUT _connector/CONNECTOR_ID/_configuration
{
  "values": {
    "tenant_id": "your-azure-tenant-id",
    "tenant_name": "mycompany",
    "client_id": "your-azure-app-client-id",
    "secret_value": "your-azure-app-secret",

    # What to sync
    "site_collections": "*",          # all sites, or ["site1", "site2"]
    "enumerate_all_sites": true,
    "use_text_extraction_service": true,  # extract text from PDFs, Word docs

    # Permissions sync (document-level security)
    "use_document_level_security": true,
    "enable_document_level_security": true
  }
}

# Trigger sync
POST _connector/CONNECTOR_ID/_sync_jobs
{
  "job_type": "full"
}

# Schedule incremental sync
PUT _connector/CONNECTOR_ID
{
  "scheduling": {
    "full": {
      "enabled": true,
      "interval": "0 0 0 * * ?"   # daily at midnight
    },
    "incremental": {
      "enabled": true,
      "interval": "0 */30 * * * ?" # every 30 minutes
    }
  }
}
```

## 🕷️ Part 6 — Web Crawler

### What is the Web Crawler?

```
Web Crawler = scrapes websites → indexes content in Elasticsearch
  → Follows links within configured domains
  → Extracts text, metadata, structured data
  → Respects robots.txt
  → Handles sitemaps
  → Supports authentication (Basic, OAuth)
  → Great for: documentation sites, public knowledge bases, support portals
```

### Create Web Crawler

```bash
# Create crawler via Kibana:
# Search → Content → Web Crawlers → New web crawler

# Or via API:
POST /api/ent/v1/internal/crawler/crawl_requests
{
  "engine_name": "my-docs-search"
}

# Via Kibana UI steps:
# 1. Search → Content → Web Crawlers → Create
# 2. Name: "Product Documentation"
# 3. Configure domains:
#    - https://docs.mycompany.com
#    - https://support.mycompany.com
# 4. Add crawl rules:
#    - Include: /docs/*
#    - Include: /support/*
#    - Exclude: /login, /api, /admin
# 5. Set crawl depth: 5
# 6. Configure sitemap URLs
# 7. Start crawl
```

### Web Crawler Configuration (YAML)

```yaml
# For self-managed web crawler
domains:
  - url: https://docs.mycompany.com
    seed_urls:
      - https://docs.mycompany.com/sitemap.xml
    crawl_rules:
      - order: 0
        policy: allow
        rule: begins
        pattern: /docs/
      - order: 1
        policy: deny
        rule: begins
        pattern: /docs/internal/

  - url: https://support.mycompany.com
    crawl_rules:
      - order: 0
        policy: allow
        rule: contains
        pattern: /articles/

# Authentication
auth:
  type: basic
  username: crawler
  password: "${CRAWLER_PASSWORD}"

# Extraction rules
extraction_rules:
  - order: 0
    policy: set
    rule: url_contains
    pattern: /blog/
    created_at: now

# Performance
max_crawl_depth: 5
request_timeout: 10
max_unique_url_count: 100000
crawl_threads: 10
```

## 🔄 Part 7 — Sync Rules & Filtering

### Basic Sync Rules

```bash
# Sync rules control which documents to ingest
PUT _connector/CONNECTOR_ID/_filtering
{
  "filtering": [
    {
      "active": {
        "rules": [
          {
            "field": "status",
            "rule": "equals",
            "value": "active",
            "order": 0,
            "policy": "include"
          },
          {
            "field": "created_date",
            "rule": "greater_than",
            "value": "2024-01-01",
            "order": 1,
            "policy": "include"
          },
          {
            "field": "category",
            "rule": "equals",
            "value": "internal_only",
            "order": 2,
            "policy": "exclude"
          }
        ],
        "advanced_snippet": {
          "value": {}
        }
      },
      "domain": "DEFAULT"
    }
  ]
}
```

### Advanced Filtering (MongoDB aggregation pipeline)

```bash
# MongoDB: use aggregation pipeline for complex filtering
PUT _connector/CONNECTOR_ID/_configuration
{
  "values": {
    "aggregation_pipeline": """
      [
        {"$match": {
          "status": "active",
          "created_at": {"$gte": {"$date": "2024-01-01T00:00:00Z"}},
          "category": {"$nin": ["internal", "draft"]}
        }},
        {"$project": {
          "password_hash": 0,
          "internal_notes": 0,
          "credit_card": 0
        }}
      ]
    """
  }
}
```

## 🔐 Part 8 — Document-Level Security (DLS)

### What is DLS with Connectors?

```
DLS = control which documents users can search based on permissions

Without DLS:
  All indexed documents visible to everyone in ES

With DLS:
  SharePoint ACLs → synced to ES → enforced at search time
  Confluence space permissions → synced → enforced
  Database row-level security → synced → enforced

HOW IT WORKS:
  1. Connector syncs document + access control list (ACL)
  2. Each document has _allow_access_control field
  3. At search time: filter by user's identity
  4. Only docs where user is in ACL returned
```

```bash
# Enable DLS on connector
PUT _connector/CONNECTOR_ID/_configuration
{
  "values": {
    "enable_document_level_security": true,
    "use_document_level_security": true
  }
}

# Trigger access control sync
POST _connector/CONNECTOR_ID/_sync_jobs
{
  "job_type": "access_control"
}

# Search with DLS enforcement
GET sharepoint-content/_search
{
  "query": {
    "template": {
      "params": {
        "access_control": ["user@mycompany.com", "group:engineering", "group:all-staff"]
      }
    }
  }
}
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| No incremental sync scheduled | Source changes not reflected | Schedule incremental sync every 15-30 min |
| Full sync too frequent | Source system overloaded | Full sync: daily max, incremental: hourly |
| No DLS for sensitive content | All users see all content | Enable DLS for SharePoint, Confluence, etc. |
| Not filtering sensitive fields | PII/passwords indexed | Use sync rules or pipeline to exclude fields |
| No error monitoring | Failed syncs silent | Monitor connector sync job errors |
| Wrong index mapping | Text not searchable | Set up index template before first sync |
| Not testing connectivity | Silent auth failures | Test from connector service host |
| Large pipeline without chunking | Huge documents in ES | Set max document size or use chunking |
| No semantic search on content | Keyword-only search | Add ELSER pipeline to connector index |
| Stale access control sync | Users see wrong docs | Schedule access_control sync frequently |

## 💡 Key Principles

```
1. Connectors = zero-code data ingestion
   → No Logstash/Beats pipeline needed for standard sources

2. Incremental sync is the key feature
   → Full sync: once, Incremental: every 15-30 min

3. DLS for all sensitive enterprise content
   → SharePoint/Confluence permissions must be enforced at search

4. Combine connector + ELSER for semantic enterprise search
   → Index SharePoint → add ELSER pipeline → semantic search

5. Web crawler for public content
   → Documentation, support articles, public knowledge bases

6. Sync rules before first sync
   → Define filtering rules before ingesting to avoid re-syncing

7. Connector client for private networks
   → When ES cannot reach internal systems directly

8. Monitor sync job errors proactively
   → Failed syncs = stale data = wrong search results

9. Pipeline processor for enrichment
   → Attach ingest pipeline to connector index for transformation

10. RAG knowledge base = connector + vector search + LLM
    → Index Confluence/SharePoint → semantic search → LLM generates answer
```
