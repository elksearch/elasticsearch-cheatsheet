## EQL - Event Query Language
### Security Use Cases, Sequence Queries, Event Correlation, SIEM, Threat Hunting

> EQL (Event Query Language) is designed for event-based data and security analytics.
> Unlike ES|QL (analytics), EQL specializes in finding patterns, sequences, and correlations across events.
> It powers Elastic SIEM's detection rules and is the language of threat hunting.

## 🧠 EQL vs ES|QL - Key Differences

```
EQL (Event Query Language):
  → Designed for SECURITY & EVENT CORRELATION
  → Finds SEQUENCES of events across time
  → Correlates events by shared entity (process, host, user)
  → Perfect for: threat hunting, SIEM rules, attack detection
  → Data model: events with category + type fields (ECS)

ES|QL (Elasticsearch Query Language):
  → Designed for ANALYTICS & OBSERVABILITY
  → Aggregates, transforms, computes metrics
  → Perfect for: dashboards, log analysis, capacity planning
  → Data model: any structured data

WHEN TO USE EQL:
  ✅ "Find all hosts where process A ran, then network B happened, then file C was created"
  ✅ "Find login from country X followed by privilege escalation within 10 minutes"
  ✅ "Detect lateral movement patterns"
  ✅ SIEM detection rules

WHEN TO USE ES|QL:
  ✅ "What is the error rate per service this hour?"
  ✅ "Show top 10 slowest API endpoints"
  ✅ Dashboards, metrics, aggregations
```

## 📋 Part 1 - EQL Syntax Fundamentals

### Basic Event Query

```eql
# Find all process creation events for powershell
process where process.name == "powershell.exe"

# Find network connections to suspicious ports
network where destination.port in (4444, 1337, 31337, 8888)

# Find file creation events
file where file.extension == "exe" and file.path : "C:\\Users\\*\\AppData\\*"

# Multiple conditions
process where
  process.name == "cmd.exe" and
  process.command_line : "*whoami*" and
  user.name != "SYSTEM"
```

### Event Categories (ECS)

```
process   → process start/stop events
network   → network connections
file      → file create/modify/delete
registry  → Windows registry changes
dns       → DNS query events
authentication → login/logout events
iam       → user/group management
host      → system events
web       → web server access
api       → API call events

# In ECS: event.category field determines the type
# Example document:
{
  "event.category": ["process"],
  "event.type": ["start"],
  "process.name": "powershell.exe",
  "process.pid": 1234,
  "host.name": "workstation-01",
  "@timestamp": "2026-05-13T10:00:00Z"
}
```

### Comparison Operators

```eql
# Equality
process.name == "powershell.exe"
process.pid != 4

# Numeric
destination.port > 1024
process.parent.pid >= 1000

# Wildcard (case-insensitive glob)
process.name like "power*"
file.path like~ "C:\\Windows\\*"   # ~ = case-insensitive

# Regex
process.command_line regex ".*base64.*decode.*"
process.name regex~ "(?i)power.*"   # ~ = case-insensitive

# IN operator (membership)
destination.port in (80, 443, 8080)
process.name in ("cmd.exe", "powershell.exe", "wscript.exe")

# NOT IN
user.name not in ("SYSTEM", "LOCAL SERVICE", "NETWORK SERVICE")

# LIKE with wildcards
file.path like "C:\\Users\\*\\Downloads\\*.exe"

# Null checks
process.parent.name == null
dns.question.name != null
```

## 🔗 Part 2 - Sequence Queries (Most Powerful Feature)

### What Are Sequence Queries?

```
Sequence = find events that happen in ORDER, sharing a common entity

Classic attack pattern:
  1. Process A creates a suspicious file
  2. THEN that file is executed
  3. THEN network connection from that process

EQL can find ALL of this in one query!
```

### Basic Sequence

```eql
# Find: cmd.exe runs → whoami runs (within 5 minutes, same host)
sequence by host.name with maxspan=5m
  [process where process.name == "cmd.exe"]
  [process where process.name == "whoami.exe"]
```

### Multi-Step Attack Sequence

```eql
# Detect: Recon → Lateral Movement → Persistence
# Classic attack chain
sequence by host.name with maxspan=30m
  [process where process.name in ("whoami.exe", "net.exe", "ipconfig.exe")]
  [network where destination.port in (445, 135, 3389)]
  [registry where
    registry.path : "HKLM\\Software\\Microsoft\\Windows\\CurrentVersion\\Run\\*"
  ]
```

### Sequence with Shared Process

```eql
# Track same process across multiple events
sequence by host.name, process.entity_id with maxspan=1h
  [process where process.name == "powershell.exe" and
   process.command_line : "*DownloadString*"]
  [file where file.extension in ("exe", "dll", "ps1") and
   file.path : "C:\\Users\\*\\AppData\\*"]
  [network where destination.ip != null and
   not cidrmatch(destination.ip, "10.0.0.0/8", "192.168.0.0/16")]
```

### Sequence with Until (Stop Condition)

```eql
# Find: login attempt → successful auth (but stop if logout happens)
sequence by user.name with maxspan=10m until [authentication where event.outcome == "failure" and failed_count > 5]
  [authentication where event.outcome == "success"]
  [process where process.name == "cmd.exe"]
```

## 🔍 Part 3 - Security Detection Patterns

### T1059 — Command and Scripting Interpreter

```eql
# Suspicious PowerShell execution
process where event.type == "start" and
  process.name : ("powershell.exe", "pwsh.exe") and
  (
    process.command_line : (
      "*-EncodedCommand*",
      "*-enc *",
      "*IEX*",
      "*Invoke-Expression*",
      "*DownloadString*",
      "*DownloadFile*",
      "*WebClient*",
      "*bypass*"
    ) or
    process.parent.name in ("winword.exe", "excel.exe", "outlook.exe")
  )
```

### T1003 - Credential Dumping

```eql
# LSASS memory access (credential dumping)
process where event.type == "start" and
  process.name : "procdump*.exe" and
  process.command_line : "*lsass*"

# OR using Mimikatz patterns
process where event.type == "start" and
  (
    process.name : "mimikatz.exe" or
    process.command_line : (
      "*sekurlsa::*",
      "*lsadump::*",
      "*kerberos::*"
    )
  )
```

### T1021 - Remote Services (Lateral Movement)

```eql
# RDP login followed by suspicious activity
sequence by host.name with maxspan=30m
  [authentication where
    event.outcome == "success" and
    winlog.event_id == 4624 and
    winlog.event_data.LogonType == "10"  # RemoteInteractive
  ]
  [process where
    process.name in ("cmd.exe", "powershell.exe", "wscript.exe") and
    not process.parent.name in ("explorer.exe", "userinit.exe")
  ]
```

### T1078 - Valid Accounts (Impossible Travel)

```eql
# Login from two different countries within short time
# (requires geo enrichment in pipeline)
sequence by user.name with maxspan=30m
  [authentication where event.outcome == "success" and
   source.geo.country_name != null]
  [authentication where event.outcome == "success" and
   source.geo.country_name != null]
  | where ?[0].source.geo.country_name != ?[1].source.geo.country_name
```

### T1071 - Application Layer Protocol (C2 Detection)

```eql
# DNS beaconing pattern
sequence by host.name, process.entity_id with maxspan=5m
  [dns where
    dns.question.name : "*.onion" or
    dns.question.name : "*.bit"
  ]
  [network where
    destination.port not in (80, 443, 53, 123)
  ]

# High-frequency beacon detection
dns where
  dns.question.name != null and
  not dns.question.name : ("*.microsoft.com", "*.google.com", "*.amazon.com") and
  dns.resolved_ip != null
| tail 1000
```

### T1110 - Brute Force

```eql
# Multiple failed logins within 5 minutes
authentication where event.outcome == "failure"
| tail 5
| where count() > 10

# OR using sequence (failed → success = successful brute force)
sequence by user.name, source.ip with maxspan=5m
  [authentication where event.outcome == "failure"] with runs=5
  [authentication where event.outcome == "success"]
```

## 🔧 Part 4 - EQL API

### Run EQL Query via API

```bash
GET /logs-*/_eql/search
{
  "query": """
    sequence by host.name with maxspan=5m
      [process where process.name == "cmd.exe"]
      [process where process.name == "whoami.exe"]
  """,
  "fetch_size": 25,
  "filter": {
    "range": {
      "@timestamp": {
        "gte": "now-24h",
        "lte": "now"
      }
    }
  },
  "fields": [
    "@timestamp",
    "host.name",
    "process.name",
    "process.command_line",
    "user.name"
  ],
  "runtime_mappings": {
    "process.command_length": {
      "type": "long",
      "script": "emit(doc['process.command_line'].value.length())"
    }
  }
}
```

## 📊 Part 6 - EQL Functions Reference

### String Functions

```eql
# length() — string length
process where length(process.command_line) > 1000

# concat() — string concatenation
file where concat(file.directory, "\\", file.name) : "*\\system32\\*"

# string() — convert to string
process where string(process.pid) : "1*"

# indexOf() — find position
process where indexOf(process.command_line, "base64") >= 0

# substring() — extract substring
file where substring(file.name, 0, 3) == "tmp"

# startsWith() / endsWith()
process where startsWith~(process.name, "power")
file where endsWith~(file.name, ".exe")

# match() — regex match
process where match(process.command_line, """.*powershell.*-[eE]nc.*""")

# wildcard() — glob match
process where wildcard(process.name, "power*", "cmd*", "wscript*")
```

### Numeric Functions

```eql
# add, subtract, multiply, divide
process where (process.uptime / 1000) > 3600

# abs() — absolute value
network where abs(destination.port - 443) < 100

# between()
network where between(destination.port, 1024, 65535)

# number() — convert to number
process where number(process.pid) > 1000
```

### Array & Null Functions

```eql
# ?. safe navigation (null-safe access)
process where process.parent?.name == "explorer.exe"

# Coalesce (null handling)
process where coalesce(process.parent.name, "unknown") == "unknown"

# cidrMatch() — IP range matching
network where cidrMatch(source.ip, "10.0.0.0/8", "192.168.0.0/16")

# arrayContains() — array field search
event where arrayContains(tags, "malware")

# arrayCount()
process where arrayCount(process.args, "*") > 10
```

### EQL Pipes (Post-Processing)

```eql
# head/tail — limit results
process where process.name == "cmd.exe"
| head 10    # first 10 events

process where process.name == "cmd.exe"
| tail 10    # last 10 events

# unique — deduplicate
process where event.type == "start"
| unique process.name

# unique_count — count unique values
process where event.type == "start"
| unique_count process.name

# sort — order results
process where event.type == "start"
| sort @timestamp asc
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| Wrong event category in query | No results | Check `event.category` field values in your data |
| maxspan too short for sequence | Sequences not found | Increase maxspan to realistic attack timeframe |
| No join key in sequence by | Sequences match across different hosts | Always add `by host.name` or relevant entity |
| Missing `event.type` filter | Too many false positives | Add `event.type == "start"` for process events |
| Using EQL for aggregations | Wrong tool | Use ES|QL for aggregations |
| Not using ECS fields | Rule doesn't work across data sources | Always use ECS field names |
| Wildcard without path separator | Wrong matches | Use `\\*` for Windows paths |
| Case-sensitive comparison | Misses variations | Use `like~` or `regex~` for case-insensitive |
| Too many detection rules | Alert fatigue | Start with high-fidelity rules, tune false positives |
| No maxspan on sequence | Performance issues | Always set maxspan for sequence queries |

## 💡 Key Principles

```
1. EQL = event correlation, ES|QL = analytics
   → Choose the right tool for the job

2. sequence by + entity = attack chain detection
   → host.name, process.entity_id, user.name are common join keys

3. maxspan is mandatory for sequences
   → Without it, performance suffers + false positives increase

4. ECS fields make rules portable
   → Rules work across different data sources with ECS

5. Sequence queries are unique to EQL
   → No other query language in ES can do this

6. MITRE ATT&CK framework organizes detection rules
   → Map every rule to a MITRE technique

7. Start with high-severity, high-fidelity rules
   → 10 good rules > 100 noisy rules

8. event.type == "start" for process events
   → Otherwise you match process stop/info events too

9. Use wildcard~ for case-insensitive glob matching
   → Windows paths and process names vary in case

10. Detection rules need continuous tuning
    → False positives must be suppressed for operational value
```
