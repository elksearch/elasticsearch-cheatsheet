## 📄 Part 1 - Document APIs (CRUD)

### Index (Create/Replace)

```bash
# Create or replace a document (auto-generates ID)
POST logs-nginx-production/_doc
{
  "@timestamp": "2026-05-16T10:00:00Z",
  "message": "GET /api/v1 200",
  "log.level": "INFO",
  "service.name": "nginx"
}
# Response: { "_id": "auto-generated-id", "result": "created" }

# Create or replace with specific ID
PUT logs-nginx-production/_doc/my-custom-id-123
{
  "@timestamp": "2026-05-16T10:00:00Z",
  "message": "GET /api/v1 200"
}

# Create ONLY (fail if document exists)
PUT logs-nginx-production/_doc/my-id?op_type=create
{ ... }
# OR:
POST logs-nginx-production/_create/my-id
{ ... }
# Returns: 409 Conflict if document already exists
```

### Get (Read)

```bash
# Get by ID (full document)
GET logs-nginx-production/_doc/my-id

# Get specific fields only
GET logs-nginx-production/_doc/my-id?_source=@timestamp,message,log.level

# Exclude fields
GET logs-nginx-production/_doc/my-id?_source_excludes=raw_message,debug_info

# Check if document exists (HEAD request — no body)
HEAD logs-nginx-production/_doc/my-id
# 200 = exists, 404 = not found

# Get multiple documents at once
POST _mget
{
  "docs": [
    { "_index": "logs-nginx-production", "_id": "id1" },
    { "_index": "logs-api-production", "_id": "id2" },
    { "_index": "logs-nginx-production", "_id": "id3", "_source": ["message"] }
  ]
}

# OR within same index:
POST logs-nginx-production/_mget
{
  "ids": ["id1", "id2", "id3"]
}
```

### Update (Partial)

```bash
# Partial update (merge with existing document)
POST logs-nginx-production/_update/my-id
{
  "doc": {
    "status": "resolved",
    "resolved_at": "2026-05-16T10:30:00Z"
  },
  "detect_noop": true   # don't update if doc unchanged
}

# Update with script
POST logs-nginx-production/_update/my-id
{
  "script": {
    "source": """
      ctx._source.retry_count += 1;
      if (ctx._source.retry_count >= 3) {
        ctx._source.status = 'failed';
      }
    """,
    "lang": "painless"
  }
}

# Upsert (update if exists, create if not)
POST logs-nginx-production/_update/my-id
{
  "script": {
    "source": "ctx._source.count += 1",
    "lang": "painless"
  },
  "upsert": {
    "count": 1,
    "first_seen": "2026-05-16T10:00:00Z"
  }
}

# Update by query (update multiple documents)
POST logs-nginx-production/_update_by_query
{
  "query": {
    "term": { "status": "pending" }
  },
  "script": {
    "source": """
      ctx._source.status = 'processed';
      ctx._source.processed_at = params.now;
    """,
    "params": { "now": "2026-05-16T10:00:00Z" },
    "lang": "painless"
  },
  "conflicts": "proceed"   # continue even if version conflicts
}
```

### Delete

```bash
# Delete single document
DELETE logs-nginx-production/_doc/my-id

# Delete with version check (optimistic concurrency)
DELETE logs-nginx-production/_doc/my-id?if_seq_no=10&if_primary_term=1

# Delete by query
POST logs-nginx-production/_delete_by_query
{
  "query": {
    "range": {
      "@timestamp": { "lt": "now-30d" }
    }
  },
  "conflicts": "proceed",
  "max_docs": 10000
}

# Delete by query async (for large operations)
POST logs-nginx-production/_delete_by_query?wait_for_completion=false
{
  "query": { "match_all": {} }
}
# Returns task ID — monitor with GET _tasks/TASK_ID
```

## 📦 Part 2 - Bulk API

### Bulk Operations (NDJSON Format)

```bash
POST _bulk
# Format: action_line\n source_line\n action_line\n source_line\n ...

# Index (create or replace)
{ "index": { "_index": "logs-nginx-production", "_id": "doc1" } }
{ "@timestamp": "2026-05-16T10:00:00Z", "message": "request 1" }

# Create (fail if exists)
{ "create": { "_index": "logs-api-production" } }
{ "@timestamp": "2026-05-16T10:00:01Z", "message": "request 2" }

# Update (partial)
{ "update": { "_index": "logs-nginx-production", "_id": "doc1" } }
{ "doc": { "status": "processed" } }

# Delete (no source line!)
{ "delete": { "_index": "logs-nginx-production", "_id": "old-doc" } }

# Another index
{ "index": { "_index": "logs-api-production" } }
{ "@timestamp": "2026-05-16T10:00:02Z", "message": "request 3" }
```

### Bulk Against Specific Index

```bash
# All operations go to logs-nginx-production by default
POST logs-nginx-production/_bulk
{ "index": {} }
{ "@timestamp": "2026-05-16T10:00:00Z", "message": "log 1" }
{ "index": {} }
{ "@timestamp": "2026-05-16T10:00:01Z", "message": "log 2" }
{ "delete": { "_id": "old-doc-123" } }
```

### Handling Bulk Responses

```bash
# Response structure:
{
  "took": 30,
  "errors": true,    # ← check this first!
  "items": [
    {
      "index": {
        "_index": "logs-nginx-production",
        "_id": "doc1",
        "status": 200,
        "result": "created"
      }
    },
    {
      "index": {
        "_index": "logs-nginx-production",
        "_id": "doc2",
        "status": 429,
        "error": {
          "type": "circuit_breaking_exception",
          "reason": "Data too large"
        }
      }
    }
  ]
}

# In client code: always check errors=true
# Extract failed items and retry only those
```

## 🔍 Part 3 - Search API Deep Dive

### Request Body Parameters

```bash
GET logs-nginx-production/_search
{
  # QUERY
  "query": { ... },

  # PAGINATION
  "from": 0,           # start offset (0-based)
  "size": 10,          # number of results (default 10, max 10000)

  # SORTING
  "sort": [
    { "@timestamp": { "order": "desc" } },
    { "_score": { "order": "desc" } },
    "_doc"             # tie-breaker (most efficient)
  ],

  # SOURCE FILTERING
  "_source": true,     # true = all, false = none, [fields] = specific
  "_source": {
    "includes": ["@timestamp", "message", "service.*"],
    "excludes": ["raw_message"]
  },

  # FIELDS API (better than _source for specific fields)
  "fields": ["@timestamp", "message", { "field": "date_field", "format": "yyyy-MM-dd" }],

  # AGGREGATIONS
  "aggs": { ... },

  # HIGHLIGHTING
  "highlight": {
    "fields": { "message": {} }
  },

  # SCORING
  "min_score": 0.5,    # filter out low-score results
  "explain": false,    # true = include score explanation
  "profile": false,    # true = include query profile

  # TRACKING
  "track_total_hits": true,   # true = exact count, false = quick estimate, N = count up to N
  "track_scores": true,       # return scores even with sort

  # SEARCH AFTER (for efficient pagination)
  "search_after": ["2026-05-15T00:00:00Z", "doc-id"],

  # TIMEOUT
  "timeout": "5s",

  # TERMINATE EARLY
  "terminate_after": 100000,  # stop after N docs (approximate results!)

  # INDICES BOOST
  "indices_boost": [
    { "logs-nginx-production": 2.0 },
    { "logs-api-production": 1.0 }
  ]
}
```

### URL Parameters

```bash
# Pretty print
GET logs-nginx-production/_search?pretty

# Human-readable values
GET logs-nginx-production/_search?human=true

# Filter path (reduce response size)
GET logs-nginx-production/_search?filter_path=hits.total,hits.hits._source

# Request timeout
GET logs-nginx-production/_search?timeout=5s

# Search type
GET logs-nginx-production/_search?search_type=dfs_query_then_fetch

# Preference (shard preference)
GET logs-nginx-production/_search?preference=_shards:0,1
GET logs-nginx-production/_search?preference=_local

# Routing
GET logs-nginx-production/_search?routing=service-a

# Scroll (deprecated, use PIT + search_after instead)
GET logs-nginx-production/_search?scroll=2m
```

### Multi-Search (Msearch)

```bash
# Run multiple searches in one request
POST _msearch
# Header line (index, settings)
{ "index": "logs-nginx-production" }
# Body line (query)
{ "query": { "term": { "log.level": "ERROR" } }, "size": 5 }
# Header
{ "index": "logs-api-production", "preference": "_local" }
# Body
{ "query": { "range": { "@timestamp": { "gte": "now-1h" } } }, "size": 10 }
# Header (empty = use default index)
{}
# Body
{ "query": { "match_all": {} }, "aggs": { "count": { "value_count": { "field": "@timestamp" } } }, "size": 0 }

# Response: array of responses, one per request
```

## 📜 Part 4 - Scroll API (Legacy — Use PIT Instead)

```bash
# Initial search with scroll context
GET logs-nginx-production/_search?scroll=2m
{
  "size": 1000,
  "query": { "range": { "@timestamp": { "gte": "now-7d" } } },
  "sort": ["@timestamp"]
}
# Response includes: _scroll_id

# Continue scrolling
POST _search/scroll
{
  "scroll": "2m",
  "scroll_id": "DXF1ZXJ5QW5kRmV0Y2gBAAAAAAABCGEW..."
}
# Each call refreshes the scroll window (2m from now)

# Clear scroll when done (frees server resources)
DELETE _search/scroll
{
  "scroll_id": "DXF1ZXJ5QW5kRmV0Y2gBAAAAAAABCGEW..."
}

# Clear ALL scroll contexts
DELETE _search/scroll/_all
```

## 📍 Part 5 - Point in Time (PIT) + search_after

```bash
# PREFERRED way for large pagination or consistent reads

# Step 1: Open PIT (snapshot current state)
POST logs-nginx-production/_pit?keep_alive=5m
# Response: { "id": "pit-id-string" }

# Step 2: First page
GET _search
{
  "size": 1000,
  "query": { "range": { "@timestamp": { "gte": "now-7d" } } },
  "sort": [
    { "@timestamp": { "order": "desc" } },
    { "_shard_doc": "asc" }    # tie-breaker for PIT
  ],
  "pit": {
    "id": "pit-id-string",
    "keep_alive": "5m"
  }
}
# Response includes sort values of LAST hit

# Step 3: Next page (use last hit's sort values)
GET _search
{
  "size": 1000,
  "query": { "range": { "@timestamp": { "gte": "now-7d" } } },
  "sort": [{ "@timestamp": "desc" }, { "_shard_doc": "asc" }],
  "pit": { "id": "pit-id-string", "keep_alive": "5m" },
  "search_after": ["2026-05-15T10:30:00Z", 12345]
}
# Each response updates pit.id — use latest one!

# Step 4: Close PIT when done
DELETE /_pit
{
  "id": "pit-id-string"
}
```

```bash
  "index": {
    "number_of_replicas": 2,
    "refresh_interval": "5s"
  }

  "properties": {

  }

# Aliases

{
  "actions": [
    { "add": { "index": "my-index-v2", "alias": "my-index" } },

# Flush

# Forcemerge
POST my-index/_forcemerge?max_num_segments=1&wait_for_completion=false

# Open/Close
POST my-index/_close
POST my-index/_open

# Clone
POST my-index/_clone/my-index-clone
{
  "settings": { "index.number_of_replicas": 0 }
}

# Shrink (reduce shard count)
POST my-index/_shrink/my-index-shrunk
{
  "settings": { "index.number_of_shards": 1 }
}

# Split (increase shard count)
POST my-index/_split/my-index-split
{
  "settings": { "index.number_of_shards": 4 }

{
  "conditions": {
    "max_age": "7d",
    "max_docs": 1000000,
    "max_primary_shard_size": "50gb"
  }
}

# Delete
DELETE my-index
DELETE logs-2024.*     # delete by pattern
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| `from` + `size` beyond 10000 | Query rejected | Use `search_after` + PIT |
| Not checking `errors` in bulk response | Silent failures | Always check `response.errors == true` |
| Scroll without cleanup | Memory leak on ES nodes | Always DELETE /_search/scroll |
| `terminate_after` for exact counts | Approximate results returned | Only use for estimation, not exact counts |
| `_source: false` without `fields` | Empty results | Use `fields` API when disabling `_source` |
| `track_total_hits: true` on huge indices | Slow count | Use `false` unless exact count needed |
| Not using `filter_path` | Large responses | Add `?filter_path=hits.total` etc |
| Regex in `_source_includes` | Not supported | Use wildcards with `*` not regex |
| Wildcard index `*` in production | Scans all indices | Use specific index patterns |
| Forgetting `?wait_for_completion=false` for long ops | HTTP timeout | Add for reindex, delete_by_query, forcemerge |

## 💡 Key Principles

```
1. search_after + PIT replaces scroll for pagination
   → More efficient, stateless, no memory leak

2. Bulk API for all production writes
   → Never single-document index in a loop

3. Always check errors: true in bulk responses
   → Partial failure is silent without this check

4. filter_path reduces response payload
   → Add ?filter_path=hits.total,hits.hits._source

5. track_total_hits=false for performance
   → Unless exact count is required

6. terminate_after gives approximate results
   → Not for exact counts, only for quick estimates

7. Cat APIs for human inspection, REST APIs for automation
   → ?format=json for cat APIs in scripts

8. wait_for_completion=false for long operations
   → Reindex, delete_by_query, forcemerge all support async

9. Optimistic concurrency with if_seq_no + if_primary_term
   → Prevents lost updates in concurrent environments

10. _mget and _msearch reduce round trips
    → Multiple operations in one HTTP request
```
