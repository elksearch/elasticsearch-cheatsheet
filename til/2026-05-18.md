## 🧠 What is OpenTelemetry?

```
OpenTelemetry (OTel) = CNCF project for unified observability
  → Single standard for Logs + Metrics + Traces + Profiles
  → Vendor-neutral: same code sends to Elastic, Datadog, Jaeger, etc.
  → Replaces proprietary APM agents for instrumentation
  → Industry standard since 2023

WHY OTEL MATTERS:
  Before OTel:  Each vendor = different SDK, different format
                Elastic APM agent, Datadog tracer, Jaeger client
                → Lock-in, migration nightmare

  After OTel:   One SDK → OTel Collector → ANY backend
                Switch from Elastic to Datadog = change config, not code
                → Zero lock-in, industry standard

ELASTIC + OTEL:
  ✅ Elastic is a founding member of OTel
  ✅ OTLP (OTel Protocol) natively supported since ES 8.x
  ✅ OTel Collector → ES is production-ready
  ✅ Elastic APM Server accepts OTLP directly
  ✅ OTel semantic conventions mapped to ECS
```

## 🏗️ Part 1 - OTel Architecture

### Complete Architecture

```
YOUR APPLICATION
    │
    │  OTel SDK (auto or manual instrumentation)
    │  → generates: Traces, Metrics, Logs
    ▼
OTel COLLECTOR (Agent mode — on same host)
    │
    │  OTLP gRPC/HTTP
    ▼
OTel COLLECTOR (Gateway mode — central)
    │
    ├──────────────────────────────────┐
    │                                  │
    ▼                                  ▼
Elastic APM Server          Prometheus (metrics)
    │                                  │
    ▼                                  ▼
Elasticsearch                  Grafana
(traces-*, metrics-*, logs-*)

OR DIRECT:
YOUR APPLICATION → OTel Collector → Elasticsearch (OTLP receiver)
```

### OTel Collector Modes

```
MODE 1: AGENT (sidecar/daemonset)
  → Runs alongside each application
  → Local collection, minimal overhead
  → Best for: Kubernetes pods, VM sidecars

MODE 2: GATEWAY (central collector)
  → Central collection point
  → Fan-out to multiple backends
  → Best for: Multi-backend, sampling, heavy processing

MODE 3: BOTH (recommended for production)
  Agent → Gateway → Backends
  → Agent: lightweight local collection
  → Gateway: batching, sampling, routing, TLS termination
```

```yaml
            enabled: true

    collection_interval: 30s

  filelog:
    include:
      - /var/log/pods/*/*/*.log
      - /var/log/myapp/*.log
    start_at: end
    include_file_path: true
    include_file_name: false
    operators:
      - type: json_parser
        timestamp:
          parse_from: attributes.time
          layout: '%Y-%m-%dT%H:%M:%S.%LZ'

    timeout: 10s

    attributes:
      - key: deployment.environment
        value: production
        action: insert
      - key: service.version
        from_attribute: app.version
        action: upsert

    detectors: [env, system, ec2, ecs, eks, gke, azure]
    timeout: 5s
    override: false

  k8sattributes:
    auth_type: serviceAccount
    passthrough: false
    extract:
      metadata:
        - k8s.pod.name
        - k8s.pod.uid
        - k8s.deployment.name
        - k8s.namespace.name
        - k8s.node.name
        - k8s.pod.start_time
      labels:
        - tag_name: app.label.component
          key: app.kubernetes.io/component
          from: pod
      annotations:
        - tag_name: ad.annotations
          key: ad.datadoghq.com/tags
          from: pod
    pod_association:
      - sources:
          - from: resource_attribute
            name: k8s.pod.ip
      - sources:
          - from: resource_attribute
            name: k8s.pod.uid

  # Transform (modify data)
  transform/logs:
    log_statements:
      - context: log
        statements:
          - set(severity_text, "INFO") where severity_text == ""
          - set(body, Concat(["[", attributes["service.name"], "] ", body], "")) where IsString(body)

  # Filter (drop unwanted data)
  filter/health_checks:
    logs:
      exclude:
        match_type: strict
        bodies:
          - "GET /health HTTP/1.1\" 200"
          - "GET /ping HTTP/1.1\" 200"

  # Tail sampling (sample based on trace characteristics)
  tail_sampling:
    decision_wait: 30s
    num_traces: 100000
    expected_new_traces_per_sec: 1000
    policies:
      - name: always-sample-errors
        type: status_code
        status_code:
          status_codes: [ERROR]
      - name: sample-slow-traces
        type: latency
        latency:
          threshold_ms: 5000
      - name: probabilistic-10-percent
        type: probabilistic
        probabilistic:
          sampling_percentage: 10

# ── EXPORTERS ──────────────────────────────────────────────

      Authorization: "Bearer ${APM_SECRET_TOKEN}"

    retry_on_failure:
      enabled: true
      initial_interval: 5s
```

```python
# Manual instrumentation
from opentelemetry import trace, metrics
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.resources import Resource, SERVICE_NAME

# Setup
resource = Resource.create({
    SERVICE_NAME: "payment-service",
    "service.version": "2.1.4",
    "deployment.environment": "production"
})

provider = TracerProvider(resource=resource)
otlp_exporter = OTLPSpanExporter(
    endpoint="http://otel-collector:4317",
    insecure=True
)
provider.add_span_processor(BatchSpanProcessor(otlp_exporter))
trace.set_tracer_provider(provider)

tracer = trace.get_tracer(__name__)

# Use in code
def process_payment(payment_id: str, amount: float):
    with tracer.start_as_current_span("process_payment") as span:
        span.set_attribute("payment.id", payment_id)
        span.set_attribute("payment.amount", amount)
        span.set_attribute("payment.currency", "INR")

        try:
            result = call_payment_gateway(payment_id, amount)
            span.set_attribute("payment.status", "success")
            span.set_status(trace.status.Status(trace.status.StatusCode.OK))
            return result
        except PaymentError as e:
            span.record_exception(e)
            span.set_status(trace.status.Status(
                trace.status.StatusCode.ERROR,
                str(e)
            ))
            raise
```

### Go

```go
// otel.go
package main

import (
    "context"
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/attribute"
    "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc"
    "go.opentelemetry.io/otel/sdk/resource"
    sdktrace "go.opentelemetry.io/otel/sdk/trace"
    semconv "go.opentelemetry.io/otel/semconv/v1.21.0"
    "google.golang.org/grpc"
)

func initTracer(ctx context.Context) (*sdktrace.TracerProvider, error) {
    conn, _ := grpc.DialContext(ctx, "otel-collector:4317", grpc.WithInsecure())
    exporter, _ := otlptracegrpc.New(ctx, otlptracegrpc.WithGRPCConn(conn))

    res := resource.NewWithAttributes(
        semconv.SchemaURL,
        semconv.ServiceName("api-service"),
        semconv.ServiceVersion("1.0.0"),
        attribute.String("deployment.environment", "production"),
    )

    tp := sdktrace.NewTracerProvider(
        sdktrace.WithBatcher(exporter),
        sdktrace.WithResource(res),
        sdktrace.WithSampler(sdktrace.ParentBased(sdktrace.TraceIDRatioBased(0.1))),
    )
    otel.SetTracerProvider(tp)
    return tp, nil
}

// Usage in handler
tracer := otel.Tracer("api-service")
ctx, span := tracer.Start(ctx, "handlePayment")
defer span.End()
span.SetAttributes(attribute.String("payment.id", paymentID))
```

## 🔗 Part 4 - Trace Context Propagation

### W3C TraceContext (Standard)

```
HTTP Headers propagated between services:
  traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
               ^^  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^  ^^
               ver         trace-id (128-bit)        span-id (64-bit)  flags

  tracestate: vendor-specific data
              elastic=...

HOW IT WORKS:
  Service A starts span → generates trace-id
  Service A calls Service B → injects traceparent header
  Service B receives → extracts trace-id → creates child span
  Service B calls Service C → propagates same trace-id
  → All services share same trace-id = distributed trace!
```

```python
# Python: automatic with auto-instrumentation
# Manual propagation example:
from opentelemetry.propagate import inject, extract
from opentelemetry import trace

# When making HTTP call (inject context into headers)
headers = {}
inject(headers)  # adds traceparent to headers
response = requests.get("http://service-b/api", headers=headers)

# When receiving HTTP call (extract context from headers)
context = extract(request.headers)
with tracer.start_as_current_span("handle_request", context=context) as span:
    # span is now child of the incoming trace
    pass
```

## 📊 Part 5 - OTel Metrics vs Prometheus

```
PROMETHEUS METRICS:
  → Pull model (Prometheus scrapes /metrics endpoint)
  → PromQL for querying
  → Well established, huge ecosystem
  → Good for: infrastructure metrics, existing setups

OTEL METRICS:
  → Push model (app pushes to collector)
  → OTLP protocol
  → Instruments at code level
  → Good for: new apps, multi-backend, code-level metrics

ELASTIC RECOMMENDATION:
  → Use OTel SDK for application metrics
  → Use OTel Collector Prometheus receiver for existing /metrics endpoints
  → Both can coexist in same collector pipeline

OTEL METRIC TYPES:
  Counter        → monotonically increasing (requests total)
  UpDownCounter  → can go up or down (active connections)
  Gauge          → current value (memory usage)
  Histogram      → distribution (request duration)
  ObservableCounter/Gauge → async callbacks
```

```python
# OTel metrics in Python
from opentelemetry import metrics
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.exporter.otlp.proto.grpc.metric_exporter import OTLPMetricExporter

# Counter
```

## 🔄 Part 7 - Migration: APM Agent → OTel

### Migration Strategy

```
OPTION 1: Side-by-side (gradual)
  → Keep APM agents for existing services
  → New services use OTel SDK
  → Both send to APM Server (accepts both)

OPTION 2: Full migration
  → Replace APM agent jar/package with OTel SDK
  → Update environment variables
  → APM Server still works (accepts OTLP)

OPTION 3: OTel Collector bridge
  → APM agent sends to OTel Collector
  → Collector forwards to APM Server
  → Used for: adding sampling, multiple backends

ELASTIC APM SERVER ACCEPTS:
  ✅ Elastic APM agents (proprietary protocol)
  ✅ OTLP gRPC (port 8200)
  ✅ OTLP HTTP (port 8200)
```

### Before/After Migration (Java)

```bash
# BEFORE (Elastic APM agent)
java -javaagent:elastic-apm-agent.jar \
  -Delastic.apm.service_name=payment-service \
  -Delastic.apm.server_url=http://apm-server:8200 \
  -Delastic.apm.secret_token=my-secret \
  -jar payment-service.jar

# AFTER (OTel agent)
java -javaagent:opentelemetry-javaagent.jar \
  -Dotel.service.name=payment-service \
  -Dotel.exporter.otlp.endpoint=http://otel-collector:4317 \
  -Dotel.resource.attributes=deployment.environment=production \
  -jar payment-service.jar
# OTel Collector forwards to APM Server via OTLP
```

## 📋 Part 8 — OTel Semantic Conventions

### Key Conventions for Services

```
SERVICE ATTRIBUTES:
  service.name        → "payment-service"
  service.version     → "2.1.4"
  service.namespace   → "com.mycompany"
  deployment.environment → "production"

HTTP SPANS:
  http.request.method  → "GET", "POST"
  url.full             → "https://api.example.com/payment"
```

## ❌ Common Mistakes & Fixes

| Mistake | Impact | Fix |
|---|---|---|
| No `memory_limiter` processor | Collector OOM under load | Always add memory_limiter as FIRST processor |
| No `batch` processor | Too many small requests to backend | Always add batch processor before exporters |
| Sampling at SDK level only | Can't change without redeployment | Use tail sampling at collector for flexibility |
| Missing service.name | All traces grouped as "unknown" | Always set service.name in resource |
| Not propagating trace context | Broken distributed traces | Ensure W3C tracecontext propagator enabled |
| Single collector, no HA | SPOF for all telemetry | Deploy collector as DaemonSet + central Gateway |
| 100% sampling in production | Storage explosion | Use tail sampling: 100% errors, 10% success |
| No queue in exporter | Data loss on backend unavailability | Enable sending_queue in all exporters |
| OTel Collector without monitoring | Can't see if collector is healthy | Expose port 8888 for collector's own metrics |
| Ignoring semantic conventions | Inconsistent field names | Always follow OTel semantic conventions |

## 💡 Key Principles

```
1. OTel = vendor neutral = no lock-in
   → Same SDK code works with Elastic, Datadog, Jaeger

2. Auto-instrumentation first, manual second
   → Zero code changes with Java/Python/Node agents

3. Collector is mandatory in production
   → Never send directly from app to backend (no buffering, no sampling)

4. Tail sampling > head sampling
   → Sample after seeing full trace — can keep all errors

5. memory_limiter + batch = always
   → First and last processors in every pipeline

6. W3C traceparent = standard propagation
   → Supported by all OTel SDKs and APM systems

7. Semantic conventions = consistency
   → service.name, http.response.status_code — always use standard names

8. OTel Operator = Kubernetes-native way
   → Auto-instrument pods with annotations, no manual agent config

9. APM Server accepts OTLP directly
   → No migration complexity — OTel → APM Server works out of the box

10. DaemonSet agent + Gateway = production architecture
    → Lightweight local collection, central batching and routing
```
